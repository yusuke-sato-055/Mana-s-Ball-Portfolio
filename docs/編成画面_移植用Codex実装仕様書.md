# 編成画面 移植用 Codex 実装仕様書

## 0. この文書の使い方

この文書は、Mana's Ball の編成画面を別ゲームへ移植するための実装仕様である。
移植先プロジェクトで Codex にこの文書を読ませ、既存の画面遷移、データ形式、描画方式に合わせて実装させることを前提とする。

クエスト選択画面、追加敵、敵グループ、戦闘パターンも移植する場合は、先に `docs/クエスト選択_敵戦闘パターン_移植用Codex実装仕様書.md` を参照すること。

この仕様の必須範囲は「クエスト選択後に、味方キャラクターを一覧から選び、出場枠・控え枠へ編成してゲームを開始する画面」である。
Mana's Ball 固有の自由試合設定、敵AI編集、能力値変更は任意拡張として後半へ分離する。

実装時は既存コードを丸ごとコピーせず、次の責務分離を維持すること。

1. キャラクターマスターは読み取り専用データとしてロードする。
2. 編集中の編成は、キャラクターIDを並べた一時状態として保持する。
3. 戦闘用キャラクターは「試合開始」を確定した時点で新規生成する。
4. UI描画、編成操作、編成検証、戦闘生成を別の関数またはクラスに分ける。

---

## 1. 元実装の参照先

Mana's Ball 内で主に参照するファイルは以下である。

| 目的 | 参照先 |
|---|---|
| 編成画面の状態・入力・描画 | `manaball/ui.py` |
| 読み取り専用キャラクター一覧 | `manaball/data.py` の `RosterCharacter`, `load_character_roster()` |
| クエスト・フィールド・試合条件の統合 | `manaball/battle_setup.py` |
| 戦闘用キャラクター生成と試合開始 | `manaball/data.py` の `create_match()` |
| キャラクターマスター | `data/csv/characters.csv` |
| クエスト定義 | `data/csv/quests.csv` |
| 人数・コスト・勝利条件 | `data/csv/match_rules.csv` |
| 敵グループ | `data/csv/enemy_groups.csv`, `data/csv/enemies.csv` |
| UI・操作テスト | `tests/test_ui.py` |
| 人数・出場/控え・試合開始テスト | `tests/test_battle_setup.py` |
| 現在の総合仕様 | `docs/実装済みの仕様.md` の「ホーム、クエスト選択、パーティー編成画面」 |

元画面の論理解像度は 1440×900。主要領域は次の通り。

- 上部: 画面タイトル、対象クエスト、敵、出場人数など。
- 左: キャラクター一覧。8件表示、スクロール可能。
- 中央上: 選択キャラクター詳細。
- 中央下: 味方・敵の能力合計とクエスト条件。
- 右: 味方編成枠と固定敵グループ。
- 下部: 追加、外す、初期編成、全解除、試合開始、戻る、メッセージ。

移植先の解像度やUIフレームワークに応じて配置は変更してよいが、情報の優先順位と操作結果は維持する。

## 2. 用語

- ロスター: 編成候補となる全キャラクターの読み取り専用一覧。
- 編成枠: キャラクターIDまたは空を保持する順序付きスロット。
- 出場枠: 試合開始時にフィールドへ配置される先頭側の枠。
- 控え枠: パーティーには参加するが初期状態ではフィールド外となる枠。
- パーティー上限: 出場と控えを合計した最大人数。
- 出場人数: 試合開始時にフィールドへ出る人数。
- コスト上限: 選択キャラクターの `cost` 合計に対する上限。0は制限なし。
- クエスト編成: クエストに紐づく敵・人数・条件を固定し、味方のみ編集する通常画面。
- 自由試合編成: 人数、敵方式、敵メンバー等も変更できる任意拡張画面。

## 3. 必須の画面遷移

```text
ホーム
  └─ クエスト
       └─ クエスト選択
            ├─ 決定 → クエスト編成
            │          ├─ 試合開始 → 戦闘
            │          └─ 戻る/Esc → クエスト選択
            └─ 戻る/Esc → ホーム

戦闘結果
  └─ 編成へ戻る → 同じクエスト・前回味方編成を復元したクエスト編成
```

クエスト選択画面から編成画面へ渡す値は、原則として `quest_id` だけにする。
編成画面を開く処理が `quest_id` からクエスト、試合ルール、フィールド、敵グループをロードする。

結果画面から戻る場合は `preserve_party=true` 相当を指定し、有効なキャラクターIDだけを重複なしで復元する。削除済みIDや現在の上限を超える末尾メンバーは破棄する。

## 4. データモデル

### 4.1 読み取り専用ロスター

最低限、次のデータを持つ。

```text
RosterCharacter
  id: string                 一意ID
  name: string
  icon_path: string?         一覧・編成枠用
  portrait_path: string?     詳細表示用
  max_hp: int
  max_resource: int          MP等。移植先の名称へ変更可
  power: int
  magic: int
  speed: int
  technique: int
  stamina: int
  cost: int
  skill_ids: ordered list<string>
  class_id: string?          フィルターを使う場合
  element_id: string?        フィルターを使う場合
  source_order: int          マスター上の表示順
```

Mana's Ball の実体は `RosterCharacter` という frozen dataclass である。
ロスターのオブジェクトへHP残量、状態異常、配置などの戦闘状態を書き込んではならない。

マスターロード時の最低限の検証:

- IDと名前が空の行は一覧へ含めず、警告ログを出す。
- IDは重複不可。
- HP等は下限値を適用する。
- 能力値はゲーム側の最小・最大へ丸める。
- 不明なクラス・属性は「不明」へフォールバックする。
- 画像欠損をデータロード失敗として扱わない。

### 4.2 クエストと試合ルール

```text
QuestDefinition
  quest_id: string
  name: string
  description: string
  field_id: string
  match_rule_id: string
  enemy_group_id: string
  enabled: bool

MatchRule
  ally_field_count: int       味方出場人数
  enemy_field_count: int      敵出場人数
  ally_party_limit: int       味方の出場＋控え上限
  enemy_party_limit: int
  ally_cost_limit: int        0なら無制限
  enemy_cost_limit: int
  score_to_win: int
  max_turns: int              0なら無制限
  substitution_enabled: bool
  injury_enabled: bool
```

ルールの事前検証:

- `1 <= field_count <= ゲームの同時出場上限`。
- `1 <= party_limit <= ゲームのパーティー上限`。
- `field_count <= party_limit`。
- 初期配置座標が出場人数分存在する。
- 味方・敵の初期配置が重複しない。
- クエストが参照するルール、フィールド、敵グループが存在する。

### 4.3 編成中だけ存在する一時状態

```text
PartySetupState
  quest_id: string
  roster: list<RosterCharacter>
  player_slots: list<string?>       長さは party_limit
  selected_character_id: string?
  selected_slot_index: int?
  roster_scroll: int
  sort_key: string
  class_filter: string?
  element_filter: string?
  message: string
  skill_loadouts: map<character_id, ordered list<skill_id>>
```

重要事項:

- `player_slots` は順序付きであり、空き枠を `null` で表す。
- 先頭 `ally_field_count` 枠が出場、それ以降が控え。
- 枠順は戦闘開始時の初期配置インデックスへ対応する。
- 同じ味方IDは複数枠へ入れない。
- 一覧で選択した状態と編成枠で選択した状態は区別する。
- UIの選択状態だけで編成済みと判断せず、常に `player_slots` を正とする。

### 4.4 戦闘開始へ渡す確定値

```text
PartyStartRequest
  quest_id: string
  ordered_player_ids: list<string>       nullを除去し、枠順を維持
  skill_overrides: map<string, list<string>>
```

戦闘側はこのリクエストとクエスト定義から、毎回新しい戦闘用キャラクターを生成する。
ロスターオブジェクトそのものを戦闘へ渡して可変状態にしない。

## 5. 画面表示仕様

### 5.1 ヘッダー

表示項目:

- タイトル「クエスト編成」。
- クエスト名。
- 敵グループ名。
- `味方出場人数 対 敵出場人数`。
- 味方パーティー上限。
- 必要に応じ、交代・負傷の有無。

通常クエスト編成では、画面内でクエストや敵グループを変更できないようにする。

### 5.2 キャラクター一覧

各行に以下を表示する。

- 顔アイコン。欠損時は円形または矩形の代替表示に名前の先頭1文字。
- 名前。
- 主要能力値。
- 編成済みなら「編成済」。
- 選択中の行は背景色と枠線を変更。

操作:

- クリックまたはタップでキャラクターを選択。
- マウスホイール、スワイプ、上下ボタンのいずれかでスクロール。
- スクロール位置は必ず `0..max(0, 件数-表示件数)` へ丸める。
- 一覧が空なら「キャラクターデータがありません」。
- フィルター結果が空なら「該当するキャラクターがいません」。

並び替えは最低限「マスター順」を実装する。任意で名前、各能力値を追加する。
能力値の降順では、同値時に `source_order` を使用して安定した順序にする。

### 5.3 選択キャラクター詳細

表示項目:

- 立ち絵。欠損時は代替表示。
- 名前。
- 最大HP、最大リソース。
- 主要能力値。
- 装備中スキル名。
- スキル変更機能を実装する場合は「スキル交代」ボタン。

一覧未選択時は操作案内を表示する。

### 5.4 チーム合計・条件

表示項目:

- 現在人数 / パーティー上限。
- 現在総コスト / コスト上限。「0」は「制限なし」と表示。
- 勝利必要点または移植先ゲームの勝利条件。
- 最大ターン。「0」は「制限なし」と表示。
- フィールド名。
- 味方と敵のHP、リソース、主要能力値合計。

味方合計は `player_slots` の非空メンバーから毎フレームまたは状態変更時に再計算する。
敵合計はクエスト固定の敵グループから計算する。出場戦力だけを比較したい場合は先頭 `enemy_field_count` 人を対象にする。

### 5.5 味方編成枠

枠数は `ally_party_limit`。

各枠に以下を表示する。

- 1始まりの枠番号。
- `index < ally_field_count` なら「出」、それ以外は「控」。
- キャラクターがいる場合はアイコン、名前、能力値。
- 空なら「空き枠」。
- 選択中の枠は強調枠線。

枠の順序は重要であり、戦闘側の初期配置へそのまま対応させる。
空欄を詰めて表示してはならない。例: `[A, null, B]` は画面でもその位置を維持する。

### 5.6 敵チーム

通常クエスト編成では敵グループを固定表示し、編集操作を出さない。

表示項目:

- グループ名、説明、必要なら能力倍率。
- 敵の順序、出場/控え、名前。
- 任意でAI名。

クエスト専用敵グループが通常の選択候補一覧に含まれない場合でも、クエストIDから直接ロードできれば試合開始可能とする。

### 5.7 フッター操作

必須ボタン:

- 味方に追加。
- 外す。
- 初期編成。
- 全解除。
- 試合開始。
- クエスト選択へ戻る。

下部に最後の操作結果またはエラーを1行で表示する。
試合開始不可の場合はボタンを無効表示してよいが、開始処理側でも必ず再検証する。

## 6. 操作仕様

### 6.1 一覧から選択

```text
onRosterSelected(characterId):
  selected_character_id = characterId
  selected_slot_index = null
  message = "追加先を選択してください"
```

### 6.2 味方に追加

追加先は、現在有効な編成枠内の最初の空き枠とする。

```text
addSelectedCharacter():
  if selected_character_id is null or master does not exist:
      error "追加するキャラクターを一覧から選択してください"
  if selected_character_id already exists in player_slots:
      error "同じキャラクターは複数編成できません"
  index = first null slot within ally_party_limit
  if index does not exist:
      error "空き枠がありません"
  player_slots[index] = selected_character_id
  selected_slot_index = index
  message = character name + "を" + (出場 or 控え) + "へ追加しました"
```

### 6.3 編成枠を選択

```text
onSlotSelected(index):
  reject if index is outside party limit
  selected_slot_index = index
  if player_slots[index] is not null:
      selected_character_id = player_slots[index]
```

空き枠を選択しただけでは一覧側の選択を消さなくてよい。

### 6.4 外す

```text
removeSelectedSlot():
  if selected_slot_index is null:
      error "外す編成枠を選択してください"
  if slot is empty:
      error "選択した枠は空です"
  player_slots[selected_slot_index] = null
  selected_slot_index = null
```

後続枠を自動的に前詰めしない。

### 6.5 初期編成

- 設定済み初期IDを順番に検証する。
- 存在しないIDと同一チーム内の重複IDは空枠へ変換する。
- 配列長を現在のパーティー上限へ合わせる。
- 出場枠が不足する場合、ロスター順で未使用キャラクターを補完してよい。
- 選択中の枠を解除する。

### 6.6 全解除

- `player_slots` をパーティー上限個の `null` にする。
- 選択中の枠を解除する。
- クエスト、敵グループ、一覧選択、フィルターは維持する。

### 6.7 戻る

- 戻るボタンと Esc は同じ処理にする。
- クエスト編成からはクエスト選択へ戻る。
- 戦闘用ゲーム状態が残っている場合は破棄し、編成中の読み取り専用状態と混在させない。

## 7. 試合開始条件

### 7.1 開始ボタンを有効にする最低条件

```text
selectedIds = non-null IDs in player_slots[0:ally_party_limit]

canStart =
  quest/setup exists
  AND len(selectedIds) >= ally_field_count
  AND len(set(selectedIds)) == len(selectedIds)
  AND fixed enemy group exists
```

控え枠は空でも開始可能。出場人数以上の味方がいればよい。

### 7.2 開始確定時の完全検証

開始ボタンの状態に関係なく、処理内で以下を再検証する。

1. クエスト、試合ルール、フィールド、敵グループが有効。
2. 味方人数が出場人数以上。
3. 味方人数がパーティー上限以下。
4. 味方IDに重複がない。
5. 全IDが現在のマスターに存在する。
6. 総コストが上限以下。上限0は無制限。
7. 敵人数が敵出場人数以上かつ敵パーティー上限以下。
8. 初期配置が双方の出場人数分あり、重複していない。
9. スキル変更を実装した場合、全スキルIDが有効で、同一枠区分の交換規則を満たす。

エラー時は戦闘へ遷移せず、原因と現在値・必要値をメッセージに表示する。

例:

- `味方が不足しています（必要 3人 / 現在 2人）`
- `味方総コストが上限を超えています（現在 18 / 上限 15）`
- `敵グループを読み込めません`

### 7.3 確定後の生成

```text
startMatch():
  validate all conditions
  ordered_player_ids = player_slots without null, preserving order
  request = PartyStartRequest(quest_id, ordered_player_ids, skill_loadouts for selected IDs)
  game = battleFactory.create(request)
  transition to battle
```

戦闘側では先頭 `ally_field_count` 人へ初期配置1..Nを割り当て、それ以降を控えにする。
味方と敵に同じマスターIDを使えるモードを追加する場合は、戦闘用IDを `player:slot`、`enemy:slot` のように別名化し、HPや状態を独立させる。

## 8. スキル交代（推奨だがゲームに不要なら省略可）

Mana's Ball では編成画面上で一時的なスキル構成を持ち、マスター自体は変更しない。

状態:

```text
skill_loadouts[character_id] = ordered skill IDs
selected_skill_slot_index
selected_skill_candidate_id
```

規則:

- 初期値はキャラクターマスターのスキル列。
- 同じスキルを複数枠へ設定不可。
- Mana's Ball では `normal` と `ball_hold` のような装備枠区分があり、異なる区分間の交換不可。
- 「初期化」で対象キャラクターだけマスター構成へ戻す。
- 結果画面から編成へ戻る場合は前回の一時構成を復元する。
- 戦闘開始時に選択メンバー分だけ override として渡す。

スキル変更が恒久保存を意味するゲームでは、別途セーブ処理を追加し、本画面の一時状態と混同しないこと。

## 9. 画像とフォールバック

推奨パス規則は次の通りだが、移植先のアセット管理へ合わせてよい。

```text
icons/{character_id}.png
portraits/{character_id}.png
```

画像がない場合:

- 一覧・編成枠: 単色背景＋名前の先頭1文字。
- 詳細立ち絵: 単色矩形＋名前の先頭1文字。
- 警告ログは初回ロード時に限定し、毎フレーム出さない。
- 画像欠損だけで編成や試合開始を禁止しない。

画像キャッシュは `character_id + requested_size` をキーにし、毎フレームの再読込・再拡縮を避ける。

## 10. 実装構成の推奨

移植先の言語・フレームワークに合わせ、次の責務を用意する。

```text
PartySetupScreen / PartySetupView
  画面遷移、描画、UIイベントを担当

PartySetupController
  追加、削除、初期化、全解除、選択、開始要求を担当

PartySetupState
  一時状態のみを保持

PartyValidator
  canStart と完全検証を担当

RosterRepository
  読み取り専用ロスターを返す

QuestRepository / MatchRuleRepository / EnemyGroupRepository
  クエストに必要な関連データを返す

BattleFactory
  確定済みID列から新しい戦闘用インスタンスを生成
```

小規模プロジェクトでは Controller と State を同じクラスにしてよいが、最低でも次を別関数にする。

- `loadPartySetup(questId, preserveParty)`
- `addSelectedCharacter()`
- `removeSelectedSlot()`
- `resetToDefault()`
- `clearParty()`
- `canStart()`
- `validateStart()`
- `buildStartRequest()`
- `draw/renderPartySetup()`

描画処理の途中で編成データを書き換えない。ただしスクロール位置を有効範囲へ丸める処理は許容する。

## 11. 任意拡張: 自由試合編成

通常編成の完成後に追加する。クエスト編成へ条件分岐を散在させず、`mode = quest | free` として明示する。

追加機能:

- 敵方式を `enemy_group` / `manual` で切替。
- 味方・敵の参加人数を各1～最大7人で変更。
- 味方・敵の出場人数を参加人数以下で変更。
- 出場超過分は控え。
- 敵手動方式では味方と同じロスターから敵枠へ追加。
- 同一チーム内は重複禁止。味方と敵の間の同一元IDは許可。
- 敵枠ごとのAIプロフィールとAIレベル。
- 初期配置座標。
- 先取点、ターン制限、交代、負傷。
- キャラクター単位またはスロット単位の能力上書き。
- 現在設定のJSON保存、再読込、マスター初期値への復帰。

自由試合の開始条件:

- 選択味方数 >= 味方出場人数。
- 味方重複なし。
- 出場人数 <= 参加人数。
- 敵グループ方式では敵グループ人数 >= 敵参加人数。
- 敵手動方式では選択敵数 >= 敵出場人数、敵側重複なし。
- 味方と敵の出場初期配置に重複なし。

通常クエスト編成では以下を表示しない。

- 敵グループ変更。
- 敵に追加。
- 敵AI変更。
- 人数・能力・配置等のデバッグ設定。

## 12. 受け入れテスト

Codex は実装後、移植先のテスト方式で最低限次を自動テストすること。

### 12.1 ロード

1. 有効なクエストIDで編成画面が開く。
2. 一覧はキャラクターマスター順で表示される。
3. 無効行は除外され、画面全体は開ける。
4. クエストに紐づく出場人数、パーティー上限、敵グループが反映される。
5. 画像欠損でも画面が開き、代替表示になる。

### 12.2 編成操作

1. 一覧選択後に追加すると最初の空き枠へ入る。
2. 同じキャラクターを再追加すると拒否される。
3. 満員時の追加は拒否される。
4. 選択枠を外しても後続枠は前詰めされない。
5. 全解除後は開始不可。
6. 初期編成で既定のメンバーと順序へ戻る。
7. 出場枠と控え枠の表示境界が `ally_field_count` と一致する。

### 12.3 開始条件

1. 必要人数未満では開始不可で、必要数と現在数を表示する。
2. 出場人数ちょうどで開始できる。
3. 控えを含む編成で開始でき、先頭N人だけが出場する。
4. コスト上限超過では開始不可。
5. コスト上限0ではコストに関係なく開始できる。
6. 敵グループ不足または欠損では開始不可。
7. 戦闘生成後のキャラクターはロスターと別インスタンスである。
8. 枠順と初期配置順が一致する。

### 12.4 画面遷移

1. 戻ると選択元のクエスト選択へ戻る。
2. 結果画面から編成へ戻ると、同じクエストと有効な前回編成が復元される。
3. 復元時に削除済みID、重複ID、上限超過分が除外される。
4. 再試合を開始しても前試合のHP・状態異常・配置が残らない。

### 12.5 スキル交代を実装する場合

1. 同区分の候補へ交換できる。
2. 重複スキルは拒否される。
3. 異なる装備区分は拒否される。
4. 初期化でマスター構成へ戻る。
5. 確定構成が戦闘側へ渡る。

```text
このリポジトリへ、添付の「編成画面_移植用Codex実装仕様書.md」に基づく編成画面を実装してください。

重要要件:
- 読み取り専用キャラクターマスター、編成中の一時状態、戦闘用インスタンスを分離する。

- 元の既存機能やユーザーの未コミット変更を壊さない。
- 関連する自動テストを追加する。

1. 関連コードとデータを調査する。
2. 変更対象と既存設計への対応関係を短く整理する。
```

## 14. 実装時の注意点

- 「開始ボタンが無効だから安全」と考えず、開始関数で完全検証する。
- キャラクターオブジェクトの参照を編成と戦闘で共有しない。
- 空き枠を除去した配列を編集中の正データにしない。枠順と空欄位置が失われる。
- 控えを「余ったメンバー」として別配列管理するより、単一の順序付き枠を出場人数で分割する方が整合しやすい。
- クエスト編成で敵を変更できるUIを誤って表示しない。
- 一覧に「編成済」と表示するだけで追加を禁止したつもりにならず、追加処理でも重複検証する。
- 結果画面から復元するときは、現在のマスターとルールで再検証する。
- コスト、人数、敵グループ等のエラーは戦闘生成層でも防御的に検証する。
- UI解像度を固定値で移植する場合でも、ウィンドウ拡縮、文字切れ、最大人数時の枠収容を確認する。
- タッチ対応では小さすぎるボタンを避け、スクロール領域とクリック領域の競合を防ぐ。

以上を満たせば、Mana's Ball と同等の基本的な編成フローを、別ゲームの構造へ安全に移植できる。
