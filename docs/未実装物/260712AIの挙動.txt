# Mana’s Ball AI機能の現状と残課題メモ
ルーズボール回収担当の補正が、無関係な主行動へ乗らないようにする修正は対応済み

## 1．このメモの目的

AIプロフィール再設計とボール状況別AIの初回実装は完了とする。

現時点のAIは、試合を成立させる基盤として使用可能な状態になっている。

今後はAI全体を作り直すのではなく、試合ログや実際のプレイで違和感が見つかった箇所について、プロフィール値、状況補正、個別行動評価を調整していく。

この文書には、初回実装後に残っている改善候補を記録する。

緊急修正ではないため、他のゲーム機能を優先し、必要になった時点で個別に対応する。

---

# 2．現在実装されているAIの概要

現在のAIは、次の情報を組み合わせて行動を決定する。

```text
試合状況
+
ボール状態
+
チーム内で割り当てられた役割
+
AIプロフィール
+
AIレベル
+
行動候補ごとの基本評価
=
最終的な行動選択
```

## AIプロフィール

AIプロフィールでは、次の項目を0～10で設定する。

* 攻撃優先度。
* パス優先度。
* 得点優先度。
* 回復優先度。
* 支援優先度。
* 奪取優先度。
* ボール保持優先度。
* ルーズボール優先度。
* 味方護衛優先度。
* 自軍ゴール守備優先度。
* MP使用。
* 危険許容。

プロフィール値を変更することで、同じキャラクターとスキル構成でも、行動傾向を変更できる。

## AIレベル

AIレベルは1～10で管理する。

AIプロフィールが「何をしたがるか」を表し、AIレベルは「候補の中からどの程度よい行動を選べるか」を表す。

低AIレベルでも、不正な行動や使用不能なスキルは選択しない。

## ボール状態

AIは、判断開始時のボール状態を次の4種類へ分類する。

* ルーズボール。
* 行動者本人が保持。
* 味方が保持。
* 敵が保持。

ボール状態に応じて、攻撃、移動、パス、奪取、守備などの評価を変える。

## チーム内役割

試合状況に応じて、各キャラクターへ次のような役割を割り当てる。

* ルーズボール回収担当。
* 回収担当の支援。
* ボール保持者。
* パス受け役。
* 味方保持者の護衛。
* 自軍ゴール守備。
* 敵保持者やパス経路の妨害。

ルーズボール時には、原則として各チームから1人を回収担当者として選ぶ。

他のメンバーは、同じボールへ全員が殺到せず、回収支援、受け位置、敵の妨害などを担当する。

# 3．現在できる調整

現在のプロフィール値と既存評価を変更することで、次の傾向は調整可能である。

## ボール回収

`loose_ball_priority`を変更することで、ルーズボール回収担当への選ばれやすさと、ボールへ接近する行動の評価を調整できる。

ただし、チーム内で誰もボールを取りに行かない状態を防ぐため、回収担当者にはボール状況による固定補正も加算される。

## 攻撃

`attack_priority`を変更することで、通常攻撃やダメージスキルの使用頻度を調整できる。

攻撃を控えさせたい場合は値を下げる。

積極的に敵を倒しに行かせたい場合は値を上げる。

## パス

`pass_priority`を変更することで、通常パスやパススキルを選ぶ傾向を調整できる。

得点へ近づくパスには、ボール状況による追加評価が加算される。

## 得点

`score_priority`を変更することで、ボール保持者が敵ゴールへ進む傾向を調整できる。

`ball_keep_priority`と組み合わせることで、自分でボールを運ぶか、早めにパスするかを調整できる。

## 奪取

`steal_priority`を変更することで、敵ボール保持者への接近、スティール、ボールカット攻撃、ボールドロップを狙う攻撃の優先度を調整できる。

## 守備

`ally_guard_priority`と`own_goal_defense_priority`を変更することで、味方保持者の護衛、自軍ゴール前の守備、敵の進路妨害の傾向を調整できる。

## MP使用

`mp_usage`を変更することで、MP消費スキルを積極的に使用するか、MPを温存するかを調整できる。

## 危険な行動

`risk_tolerance`を変更することで、敵に囲まれた位置、成功率の低いパス、危険な前進などをどの程度許容するか調整できる。

# 4．初回実装後の確認結果

## 改善できた点

以前は、ルーズボールが存在していても、双方がボールを無視して攻撃を繰り返すことが多かった。

現在は、ルーズボール回収担当と回収支援役が設定され、ボールへ向かう行動が発生している。

味方側にも、新しいAIプロフィールが適用されるようになった。

確認時の主なプロフィールは次のとおり。

* ブリギッドは攻撃型。
* イシスは回復型。
* ゼフィリアは奪取型。
* ロザリアとマリナは攻撃型。

3対3では、ブリギッドが2得点し、イシスがパス、ゼフィリアがスティールを行った。

5対5でも、ロザリアが得点し、味方と敵の双方でパス、守備、妨害が発生した。

以前のように、攻撃だけを繰り返して試合が停滞する状態からは改善している。

## 現在の評価

現在のAIは、完成済みの個別AIではなく、ログを見ながら数値と評価を調整できる共通基盤として成立している。

キャラクターごとの細かい性格付けは、今後プロフィールや役割設定を変更して対応する。

# 5．残課題1：回復AI

## 現在の問題

回復型プロフィールは適用されているが、実際にはHP回復より次の行動が選ばれる場合が多い。

* MP回復。
* 攻撃。
* パス。
* 移動。
* 待機。

確認ログでは、イシスが回復型であるにもかかわらず、HP回復スキルの使用が少ない。

敵の支援兵も、HP回復よりMP回復や攻撃を行う場合がある。

これは回復プロフィールが未適用なのではなく、HP回復候補の基本評価が、他の候補より低くなっている可能性が高い。

## 将来対応したい内容

### HP割合による回復開始条件

対象の現在HP割合が一定以下の場合に、回復候補を強く評価する。

例として次のような設定を検討する。

```text
heal_start_hp_percent
HP回復を積極的に検討し始める割合。
```

例：

* 80なら、HP80％以下から回復候補を評価する。
* 50なら、HP50％以下まで回復を控える。
* 30なら、瀕死時のみ回復する。

### 緊急回復条件

HPが一定割合以下の場合は、通常のAIプロフィール値より強い緊急補正を加える。

例：

```text
HP25％以下の味方がいる場合
HP回復を最優先候補群へ入れる。
```

### HP回復とMP回復の分離

現在は、HP回復とMP回復が回復または支援の評価内で混在している可能性がある。

将来的には、次の設定を分けることを検討する。

```text
heal_priority
HP回復の優先度。

mp_recovery_priority
MP回復の優先度。
```

プロフィール項目を増やしたくない場合は、CSV列を追加せず、行動評価内で次の判定を行う。

* HPが危険な味方がいる場合はHP回復を優先。
* HPが安全でMPが不足している場合はMP回復を優先。
* HPとMPが十分な場合は、回復行動を選ばない。

### 回復対象の選択

回復対象は、単純な減少HP量だけでなく、次を考慮する。

* 現在HP割合。
* 予想される戦闘不能の危険。
* ボール保持者か。
* ルーズボール回収担当か。
* 得点可能なキャラクターか。
* 敵の攻撃範囲内か。
* 実際に回復できる量。
* 過剰回復量。

### 自己回復と味方回復

自分を回復するか、味方を回復するかの評価も必要になる可能性がある。

回復役本人が危険な場合は自己回復を優先する。

ただし、得点直前の保持者や戦闘不能直前の味方がいる場合は、味方回復を優先する。

## 回復AIの実装を依頼する場合の概要

後日対応する場合は、次の内容を中心に仕様化する。

```text
回復型AIがHP回復よりMP回復や攻撃を選びやすいため、
対象HP割合、緊急度、実回復量、過剰回復量を評価し、
必要な場面でHP回復を優先するようにしたい。

HP回復とMP回復の評価を分離し、
HPが危険な味方がいる場合はHP回復、
HPが安全でMPが不足している場合はMP回復を選択させたい。

回復開始HP割合は、CSVまたは共通設定から調整できるようにしたい。
```

# 6．残課題2：裏取りと受け位置

## 現在の状態

味方がボールを保持している場合、他の味方は`receiver`としてパス受け位置へ移動する。

ただし、現在は「パスを受けられる位置」を評価している段階であり、敵守備者の背後やゴール前の空きマスへ走り込む明確な裏取りまでは実装されていない。

## 将来対応したい内容

* 敵ゴール側の空きマスを優先する。
* 敵守備者より前方へ走る。
* ボール保持者と同じ列だけでなく、斜め前方へ展開する。
* パスカット範囲を避ける。
* パス成功率と得点までの距離を同時に評価する。
* 味方同士が同じ受け位置へ集中しないようにする。
* ボール保持者から遠すぎる位置を避ける。

## 設定方式の候補

現在の項目で調整する場合は、次を組み合わせる。

* `pass_priority`
* `score_priority`
* `risk_tolerance`
* 受け位置の基本評価

より明確に制御したい場合は、将来的に次の設定を追加する。

```text
run_behind_priority
敵守備者の背後へ抜ける優先度。
```

ただし、項目数を増やす前に、既存の受け位置評価を調整して対応できるか確認する。

# 7．残課題3：ルーズボール回収担当の主行動

## 現在の問題

ルーズボール回収担当者は、ボールへ接近する移動を行っても、その後の主行動として次を選ぶ場合がある。

* MP回復。
* 攻撃。
* 支援スキル。
* 待機。

これは、移動先がボールへ近づいていることを理由に、移動後の行動計画全体へ回収担当用の状況補正が加算されている可能性がある。

## 例

回収担当者がボールへ接近した後、MP回復を使用した場合でも、ログ上では「回収担当のボール接近」という大きな状況補正が行動全体へ付いている。

この動きは完全な不正ではないが、プレイヤーから見ると「回収担当なのにボールを拾わず別行動をした」と感じる可能性がある。

## 将来対応したい内容

移動目的と主行動目的を分離して評価する。

```text
移動評価
ボールへ近づいたか。

主行動評価
取得、攻撃、回復、支援など、移動後に何を行うか。
```

回収担当用の大きな補正は、次の行動だけへ適用する。

* 直接ボールを取得する。
* 次の行動で取得可能な位置へ進む。
* 敵の回収を明確に妨害する。
* ボール取得経路を確保する。

MP回復や無関係な支援には、回収担当の大きな補正をそのまま適用しない。

# 8．残課題4：ボール状況補正とプロフィール補正の強さ

## 現在の状態

ボールを無視する問題を防ぐため、ボール状況補正には大きな固定値が使用されている。

例：

* 直接取得に大きな加点。
* ボールへの接近に大きな加点。
* パス受け位置に大きな加点。
* 敵保持者への対応に大きな加点。

この仕組みにより、ボール競技としての最低限の行動は保証されている。

## 懸念点

固定の状況補正が強すぎる場合、AIプロフィールの数値を変更しても、最終行動がほとんど変化しない可能性がある。

例として、回復型でルーズボール優先度が低くても、直接取得の固定加点によってボールを取得する。

これは試合成立のためには正しいが、プロフィールによる個性が弱くなる。

## 将来対応したい内容

状況補正を、完全な固定値ではなく、プロフィール値に応じて変化させる。

例：

```text
最終状況補正
=
基準状況補正
×
プロフィール係数
```

ただし、誰もボールを取りに行かない状態を防ぐため、最低保証値は残す。

```text
直接取得可能な回収担当者
最低でも取得候補を上位候補群へ入れる。
```

調整時は、次の関係を維持する。

```text
ルーズボール回収担当者の直接取得
>
ボールと無関係な通常攻撃
```

一方で、次のような例外は認める。

* 敵回収担当を確実に戦闘不能にできる。
* 攻撃でボール取得経路を確保できる。
* 攻撃後も同じターンに取得できる。
* 自軍ゴール直前の緊急防衛。

# 9．残課題5：プロフィールの細分化

現在の12項目で、基本的な性格付けは可能である。

ただし、今後より細かいAIを作る場合、次の項目が不足する可能性がある。

* HP回復とMP回復の個別優先度。
* 裏取り優先度。
* 自己回復と味方回復の差。
* 敵との理想距離。
* 味方保持者との理想距離。
* 強化スキルと回復スキルの個別優先度。
* 得点より安全なパスを選ぶ傾向。
* 危険なパスを選ぶ傾向。

ただし、項目を増やしすぎると、再び人間が管理しにくいAIプロフィールになる。

新しい項目は、既存項目と状況評価だけでは明確に調整できないことを、複数の試合ログで確認してから追加する。

# 10．今後のAI調整方法

今後AIの違和感を修正する場合は、次の流れで行う。

1．対象となる試合ログを保存する。

2．違和感のあるキャラクターと行動番号を特定する。

3．AI判断欄から次を確認する。

* AIプロフィール。
* AIレベル。
* 判断開始時ボール状態。
* チーム内役割。
* 基本評価。
* ボール状況補正。
* AIプロフィール補正。
* MP補正。
* 危険補正。
* 最終評価。
* 選択理由。

4．問題が次のどこにあるか分類する。

```text
候補が生成されていない。
基本評価が不適切。
ボール状況補正が強すぎる。
プロフィール補正が弱すぎる。
役割割当が不適切。
AIレベルによる選択範囲が不適切。
```

5．必要な箇所だけを修正する。

6．同じ試合条件と同じ乱数シードで再実行する。

7．複数シードでも極端な挙動が発生しないことを確認する。

# 11．今後GPTへ渡せる依頼例

## 回復AI

```text
添付ログでは、回復型AIがHP回復よりMP回復や攻撃を優先しています。

HP割合、実回復量、過剰回復量、戦闘不能の危険度を評価し、
必要な場面ではHP回復を優先するようにしたいです。

HP回復とMP回復の評価は分離してください。

回復開始HP割合をCSVまたは共通設定から調整できるようにしてください。

既存AIプロフィールとボール状況別評価は維持してください。
```

## 裏取りAI

```text
味方ボール保持時の受け役が、
保持者の近くや横方向へ移動することが多いため、
敵ゴール側の空きマスと敵守備者の背後を評価するようにしたいです。

パス成功率、
パスカット範囲、
得点までの距離、
味方との位置重複を考慮してください。

まずは新しいCSV項目を追加せず、
既存の受け位置評価とscore_priority、
pass_priority、
risk_toleranceで調整できるか検討してください。
```

## ルーズボール担当

```text
ルーズボール回収担当者が、
ボールへ接近した後にMP回復や無関係な支援を行う場合があります。

移動目的と主行動目的を分離して評価してください。

回収担当用の大きな状況補正は、
直接取得、
取得可能位置への接近、
敵回収担当の妨害、
取得経路確保へ限定してください。

移動後の無関係な回復や支援へ、
回収担当補正をそのまま適用しないでください。
```

## プロフィール補正

```text
ボール状況補正が強く、
AIプロフィール値を変更しても行動差が出にくい可能性があります。

ボール状況補正とプロフィール補正の比率を調査し、
ボールを無視しない最低保証を残しつつ、
プロフィール値による性格差が出るように調整してください。
```

# 12．現時点の終了判断

AIプロフィール、
AIレベル、
味方と敵の共通評価、
ボール状態別評価、
ルーズボール回収担当、
受け位置、
守備、
敵保持者対応、
判断ログの基盤は実装済みとする。

現在確認されている残課題は、ゲーム進行を停止させる致命的な不具合ではない。

回復AI、
裏取り、
回収担当の主行動、
補正比率については、今後の試合バランス調整として対応する。

そのため、AI関連の初回実装は現状で終了とし、次のゲーム機能実装へ進む。
