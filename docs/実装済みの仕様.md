## 1. ゲーム概要

Python 3.11とPygame 2系で動作する、可変人数のターン制ファンタジー球技SRPG。

- 11×5、13×5、15×7など、フィールドレイアウトに応じた可変サイズの盤面。
- 戦闘エンジンの同時出場上限は既存6対6を維持し、クエスト用の最大同時出場人数は5人、パーティー総人数上限は各チーム7人。
- クエスト試合はクエスト設定に応じて1対1～6対6とベンチを扱う。自由試合は各チーム最大7人の参加人数と出場人数を分けて扱う。
- ゴール範囲、ボール初期位置、初期配置、リスタート配置は `data/field_layouts.json` のレイアウトから解決する。
- 素早さ順のラウンド制。
- 攻撃、移動、ボール、スキル、待機の5基本コマンドと、各コマンド配下の通常行動・派生スキル。手動操作中のコマンド末尾には、戦闘状態を変更しない確認専用の「能力」ボタンを表示する。
- 防御、攻撃スキル由来のボールカット／ドロップ、独立スキルのスティールなどの行動処理。全キャラクター共通の通常カットは通常ゲームの候補から廃止済み。
- ボール取得、保持、奪取、パスカット、得点。
- 敵ZOCと味方ユニットの通過。
- キャラクターの正式能力はパワー、マジック、スピード、テクニック、スタミナの5種類。職種・属性マスターは廃止済み。
- 物理攻撃はパワー、魔法攻撃と回復はマジック、両防御はスタミナを参照する。物理・魔法はキャラクター能力ではなくスキル分類として維持する。
- 試合中に増減するリソースはHPとMP。スタミナはパワーなどと同じ固定能力。
- MP、射程、ボール状態、クールタイム、使用回数、移動後使用可否、保持・奪取・争奪状態によるスキル制限。旧物理・魔法技能レベル制限は廃止済み。
- 行動演出、判定パネル、上部行動順アイコン。
- 敵AIとプレイヤーチームのオート操作。
- 行動順の一巡では終了せず、2点先取までターン周期を継続。
- 移動演出後の確認と、主行動確定前の移動キャンセル。
- 常設ログを置かず、全ログ画面で試合中ログを閲覧・コピー。
- 試合レポートは常にメモリ上で収集・Markdown生成する。通常プレイは `log/play/`、CIは `log/ci/` へ保存し、自動テストと通常のローカルヘッドレスは保存しない。
- 得点後は失点側が再開時のボール保持者を選択。
- ホーム画面の「クエスト」からクエスト選択、クエスト用パーティー編成を経由し、選択クエストのフィールド、試合条件、敵グループで試合開始。
- 敵マスターCSVと敵グループCSVから最大7体の敵パーティーを生成し、通常試合画面、CLI、テスト、`create_match(enemy_group_id=...)` から既存試合へ接続できる。
- ホームの「自由試合」から、敵グループ方式または敵手動編成方式を選び、人数、能力、敵AIプロフィール、初期配置、先取点、ターン制限、交代、負傷を一時変更して試合開始。
- 確認モーダル付きのリタイア。通常試合では味方敗北、自由試合では勝敗なしの中断として終了。
- 味方オートと敵AIは同じAIプロフィール・AIレベル・ボール状態別評価を使用する。味方プロフィールの直接編集・保存画面は持たず、未設定時は既存AI役割からプロフィールを解決する。

## 4. 実行経路

```text
main.py
  └─ GameApp
       ├─ ホーム（内部状態名は title）
       │    ├─ クエスト → クエスト選択 → クエスト用パーティー編成
       │    └─ 自由試合 → 敵方式、人数、能力、AI、配置、条件の一時設定
       ├─ create_match(player_ids, enemy_ids, enemy_group_id, 各種override)
       │    ├─ load_config()
       │    ├─ load_ai_profiles()
       │    ├─ load_skills()
       │    ├─ enemy_group_id指定時
       │    │    ├─ load_enemy_masters()
       │    │    ├─ load_enemy_groups()
       │    │    └─ build_enemy_group_match_inputs()
       │    └─ load_characters()へ通常キャラクター形式で接続
       ├─ 手動入力 ─┐
       └─ AI判断 ───┴─ MatchGameの同一行動処理
                          ├─ ActionResult
                          │    └─ UI演出キュー
                          └─ MatchReportCollector
                               ├─ 行動前後・システムイベント記録
                               ├─ メモリ上のMarkdown生成
                               └─ play/ci指定時だけファイル保存
```

判定は `MatchGame` で1回だけ実行し、UIは `ActionResult.details` を表示する。同じ乱数判定やダメージ処理を演出用に再実行しない。攻撃、カット、パスのプレビューも実行処理と同じ共通計算を使い、プレビュー時は乱数を生成しない。`MatchReportCollector` は行動の前後状態と確定済みの `ActionResult` を記録し、判定やダメージをログ出力用に再計算しない。

## 5. `core.py` の主要データ

### `MatchConfig`

フィールド、勝利条件、ダイス、回復率、演出時間などを保持する。値は原則 `match_settings.csv` から読み込む。

今回の能力差・ボール行動で使用する主な設定:

- `field_width`, `field_height`: クエストまたは上書き設定から解決した盤面サイズ。初期データは11×5、13×5、15×7。
- `left_goal_x_start`, `left_goal_x_end`, `right_goal_x_start`, `right_goal_x_end`, `goal_y_start`, `goal_y_end`: レイアウトのゴールセルから算出したゴール範囲。
- `global_damage_multiplier`: 攻撃ダメージ全体倍率。標準0.6。
- `damage_difference_rate`: 能力差1あたりの割合補正。標準0.05。`damage_difference_min`～`damage_difference_max`（標準-0.25～+0.25）へ制限する。
- `healing_multiplier`: HP回復スキル全体倍率。標準0.65。
- `normal_cut_base_rate`: 廃止済みの旧通常カット互換用設定。通常ゲームの候補生成では使用しない。
- `pass_cut_base_rate`: パスカット基礎成功率。標準35％、下限25％、上限45％。
- `ability_rate_multiplier`: 能力差1あたりの成功率補正。標準5％。
- `success_rate_min`, `success_rate_max`: 通常成功率の下限5％、上限95％。
- `base_pass_range`: 基本パス射程。標準3。
- `pass_distance_grace`: 距離補正なしの距離。標準3。
- `pass_distance_penalty`: 超過1マスごとのパス値減少。標準1。
- `enemy_ai_profile_ids`: 初期敵編成の各スロットに適用するAIプロフィールID。空欄または存在しないIDの場合はキャラクター側の初期AIまたは標準AIへフォールバックする。
- `default_enemy_group_id`: 通常試合で初期選択する敵グループID。不正・無効・未設定の場合は表示順が最初の有効グループへフォールバックする。
- `player_team_size`, `enemy_team_size`: チーム別の同時出場人数。0の場合は共通の `team_size` を使用する。戦闘エンジン上限は既存6対6を維持する。
- `player_party_limit`, `enemy_party_limit`: 出場メンバーとベンチを含むパーティー総人数上限。クエスト/自由試合では最大7人。
- `turn_limit`: 0はターン周期による終了なし。1以上の場合は指定周期の全員行動後に試合終了する。
- `debug_mode`: 自由試合かどうか。内部互換名として残り、リタイア時の終了理由にも使用する。

`max_rounds`、`score_stamina_recovery_rate`、`stamina_per_turn`、`wait_stamina_recovery_rate` は旧設定読込の互換用に残るが、通常の終了条件やスタミナ増減には使用しない。

### 能力パラメーターの分類

「能力」は、物理・魔法の「系統」と、パワー・スピード・テクニック・スタミナの「基礎能力」に分類する。

```text
能力
├─ 系統
│  ├─ 物理
│  └─ 魔法
└─ 基礎能力
   ├─ パワー
   ├─ スピード
   ├─ テクニック
   └─ スタミナ
```

- 系統: 行動が物理系か魔法系かを表し、攻撃、パス、カットなどで使用する系統値を決める。
- 基礎能力: 系統値と組み合わせて、威力、行動順、精密操作、防御などを決める。
- パワー: 主に攻撃値と威力へ使用する。
- スピード: 行動順、移動力段階、パスカット可能範囲へ使用する。
- テクニック: カット、ボール保持、パス、パスカットの中心能力。
- スタミナ: パワー、スピード、テクニックと同じ1～10の固定能力。防御値や回復量などから参照するが、試合中に消費・回復するゲージではない。
- `physical_skill_level` と `magic_skill_level` は各系統のスキル使用条件であり、系統値そのものとは別の値。

### `Character`

主な基本データ:

- `class_id`, `class_name`
- `element_id`, `element_name`
- `max_hp`, `hp`
- `max_mana`, `mana`。画面上ではMP表記。
- `physical`, `magic`: 系統値。
- `primary_system`: 試合開始時に確定する固定主系統。`physical` または `magic`。一時的な能力増減で変化しない。
- `power`, `speed`, `technique`, `stamina`: 基礎能力。
- `physical_skill_level`, `magic_skill_level`
- `move_range`
- `ai_role_id`, `ai_role_name`: 味方と敵が共通利用するパワー型、テクニック型、支援型の役割。未設定時はスキルと能力から自動判定する。
- `default_ai_profile_id`, `default_ai_level`: 敵マスター由来の基本AIプロフィールとAIレベル。AIレベル空欄は5。
- `ai_profile_id`, `ai_profile_name`, `ai_profile_description`, `ai_level`: 試合開始時に確定した味方・敵共通のAI情報。
- `ai_settings`: 12種類の0～10プロフィール値。味方オートは未設定時にAI役割から有効プロフィールを解決する。
- `ai_profile_source`: `character`、`enemy_master`、`enemy_group`、`enemy_slot`、`role_mapping`、`fallback` の決定元。
- `enemy_master_id`, `enemy_type_id`, `enemy_group_id`, `enemy_group_slot`, `enemy_scale`: 敵グループから生成した個体の元データ情報。通常キャラクターでは空値または既定値。
- `image_id`: 敵マスター側の任意画像ID。未設定・画像欠損でも既存の文字表示へフォールバックする。

`attack`、`defense`、`accuracy`、`evasion`、`magic_defense`、`pass_range`、`breakthrough`、`breakthrough_defense` は旧CSV読込の互換用フィールドとして残す。現在の主系統基本攻撃、攻撃由来のボール効果、通常パスでは直接参照しない。

既存CSVの以下の列は、新しいボール行動の補正値として再利用する。列がない、空、または不正な場合は0として読み込む。

- `pass_power`: パス補正。
- `pass_cut`: パスカット補正。
- `ball_keep`: ボールキープ補正。
- `ball_cut`: 廃止済みの旧通常カット互換用補正。攻撃スキル由来のカットには加算しない。

### 敵マスターと敵グループ

`data/csv/enemies.csv` は敵単体のマスターデータを保持する。初期データは `training_power`、`training_magic`、`training_support` の確認用3体。

- `enemy_id`, `enemy_type_id`, `name`, `element_id`, `class_id`, `image_id`
- 最大HP・MP、物理・魔法、パワー・スピード・テクニック・スタミナ
- 物理・魔法技能レベル、移動力、`primary_system`
- `skill_slot_1`～`skill_slot_3`: 最大3件の装備スキル。空欄可。同一敵内の重複、標準行動、存在しない・無効なスキル、技能レベル不足はデータ不正。
- `default_ai_profile_id`, `enabled`, `notes`

`data/csv/enemy_groups.csv` は敵グループを保持する。空欄スロットは未使用で、旧3体・6体グループをそのまま読み込める。初期データは `training_group`、`training_2v2_group`、`training_3v3_group`、`training_large`、`training_5v5_group`。

- `enemy_1_id`～`enemy_7_id`: 敵マスターID。同じIDを複数枠へ指定可能。
- `enemy_scale`: 空欄は1.0。0以下、数値変換不能、NaN・無限値はデータ不正。
- `group_ai_profile_id`: グループ共通AI。
- `enemy_1_ai_profile_id`～`enemy_7_ai_profile_id`: スロット別AI。
- `enemy_1_ai_role_id`～`enemy_7_ai_role_id`: スロット別AI役割。
- `display_order`, `enabled`, `description`

AIプロフィールは「標準AI → 敵マスター基本AI → グループ共通AI → スロット別AI」の順で上書きする。空欄は直前の設定を維持し、未登録IDは警告して直前の有効設定へフォールバックする。

`enemy_scale` は敵マスターを変更せず、試合用個体の最大HP・最大MPと6能力だけへ適用する。正の値は小数第1位を四捨五入し、HP・MPは最低1、6能力は `MatchConfig` の能力範囲へ補正する。技能レベル、移動力、スキル、AI設定、クールタイムには適用しない。

試合中個体IDは `enemy:<enemy_group_id>:<slot>`。同じ敵マスターを複数枠へ指定しても、HP、MP、位置、状態、クールタイム、使用回数は独立する。変換後は通常キャラクターと同じ `Character`、AI、スキル、得点、戦闘不能、レポート処理を使用する。

クエスト/自由試合の敵グループ方式では、グループ人数が敵出場人数未満なら開始不可、敵パーティー上限を超える場合も開始不可。出場人数を超えた敵は編成順を維持してベンチになる。

実装済みの入口は `create_match(enemy_group_id=...)`、`create_enemy_team()`、CLIの `--enemy-group`、クエスト試合、自由試合。自由試合の敵グループ方式は味方IDと敵グループIDを渡し、敵手動編成方式は味方IDと敵IDを渡す。再試合と結果画面からの設定復帰では敵方式、敵グループID、手動敵IDを引き継ぐ。

### 共通AIと敵AIプロフィール

敵AIプロフィールは `data/csv/ai_profiles.csv` で管理する。味方にはプロフィールや保存済み調整値を適用せず、AI役割、能力、スキル、所属チームと試合状態から共通行動計画を作成する。

AI設定値はすべて0～100の整数で、50が標準。空欄や数値変換不能は50、0未満は0、100超過は100へ補正する。プロフィールIDが未設定または存在しない場合は警告し、標準型AIを使用する。重複したプロフィールIDは警告して後続行を無視する。

初期データとして以下を持つ。

- `standard`: 標準型。原則すべて50。
- `attack`: 攻撃型。接近、攻撃、MP使用を高める。
- `defense`: 守備型。安全移動、護衛、進路妨害を高める。
- `score`: 得点型。ゴール接近と突破を高める。
- `support`: 支援型。回復、支援、味方追従を高める。
- `steal`: ボール奪取型。敵保持者への接近、妨害、奪取を高める。

AI設定項目は以下の4分類で扱う。

- 基本行動: 攻撃性、危険許容度、MP使用頻度、ゴール優先度、パス積極性、味方追従度、敵妨害度、支援優先度。
- ボール所有時: ゴール接近、安全移動、味方連携、敵陣突破、危険時パス、ボールスキル。
- ボール非所有時: ボール所有者護衛、所有者追従、敵進路妨害、裏取り、パス受け位置、味方支援、ボール奪取。
- 回復・支援: 自己回復、味方回復、ボール所有者回復、状態異常解除、得点役支援、回復開始HP割合。

敵AI設定の適用順は以下。

1. 標準AI設定。
2. 敵キャラクターの `default_ai_profile_id`。
3. 敵編成スロット側 `enemy_ai_profile_ids`。
4. 戦闘中の状態・役割・方向評価。

味方と敵は同じ候補生成・優先段階・実行処理を通る。ゴール方向は所属チームと実際のゴール領域から毎行動算出し、得点後にはAI計画、移動履歴、パス履歴を破棄する。

主な試合状態:

- `off_field`: 戦闘不能で盤面外。
- `acted`: 行動済み。
- `waiting`: 待機済み。
- `defending`: 防御中。
- `keeping`: ボールキープ中。
- `disabled`: 行動不能。
- `temporary_effects`: 移動低下など。
- `skill_cooldowns`: スキルIDごとの残りクールタイム。
- `skill_use_counts`: スキルIDごとの試合中使用回数。
- `reaction_skill`: 同時に1件だけ保持する反応待機情報。

### `Ball`

ボール保持者の正は `Ball.holder_id`。キャラクター側へ重複した保持フラグは持たない。

- 保持者がいる場合、ボール位置は保持者位置から取得。
- 保持者がいない場合だけ `loose_position` を使用。
- 変更は `set_ball_holder()` または `drop_ball()` を使う。

### `Skill`

各スキルは、効果の既存メタデータに加えて以下を保持する。

- `skill_system`: `physical`、`magic`、`common`。
- `skill_type`: `power`、`speed`、`technique`、`stamina`。
- `required_level`: 必要な物理または魔法スキルレベル。
- `allowed_states`: `possession`、`acquisition`、`contest`、`always`。
- `resource_type`, `resource_cost`: `mana`、`none` と消費量。旧 `stamina` 指定は読込時に消費なしへ移行する。
- 行動側・防御側の主能力と副能力。
- 不正データの場合の `validation_error`。この値があるスキルは使用不可。
- `category`: `normal`、`single`、`basic`、`advanced`。
- `activation`: `active`、`reaction_wait`、`reaction`、`automatic`。
- `min_range`, `range`: 最小・最大射程。
- `cooldown`, `max_uses`: 自分の行動開始単位のクールタイムと1試合の使用上限。
- `purpose_tag`: AI評価用の用途。
- `effect_mode`: 新しい共通効果方式は `common`、既存互換処理は `legacy`。
- `effects`: `skill_effects.csv` から効果順で読み込んだ最大5件の `SkillEffect`。
- `command_group`: 画面上の所属コマンド。`attack`、`move`、`ball`、`skill`、`wait`。旧 `pass` は読込時だけ受け付け、警告して `ball` へ変換する。
- `usable_after_move`: 通常移動または仮移動後に使用できるか。強化、弱体化、攻撃、回復、防御、ボール関連行動は原則 `true`、影渡り・突破など使用者自身が移動する行動は `false`。
- `display_order`: 同一コマンド内の表示順。小さい値を先に表示する。

共通効果方式では、スキルIDごとの処理分岐を使わず、効果種別ごとの共通処理を順番に実行する。対応済み効果は `damage`、`modify_stat`、`heal_hp`、`recover_mp`、`prepare_reaction`、`drop_ball`、`steal_ball`、`force_move`、`pass`、`guard`。

事前条件と対象をすべて検証してからMPを消費し、必要なら成功判定を1回だけ行う。全効果はその判定結果を共有する。効果途中の予期しない例外では、HP、MP、位置、ボール、一時効果、クールタイム、使用回数を実行前へ戻す。共通スキルは物理・魔法ともMPを使用でき、スタミナは消費しない。物理・魔法スキルレベル条件はCSVの `required_level` に従う。

`force_move` は使用者から対象を遠ざける1マス押し出し、`guard` は既存の防御状態付与として共通実行する。`pass` は `distance` を射程加算として扱い、通常パスと同じ固定主系統、対象検証、経路、受動・反応パスカット、得点判定へ接続する。

チーム状態は `Ball.holder_id` から都度算出する。自軍保持は保持状態、相手保持は奪取状態、保持者なしは両軍とも争奪状態であり、別の状態変数へ重複保存しない。

### `ActionCandidate`

攻撃、移動、ボール、スキル、待機の各ボタンから表示・実行する行動候補。通常行動と習得スキルを同じ形式へ変換し、UIとAIの使用可否判定を共通化する。

主な項目:

- `action_id`: `standard:move`、`standard:pass`、`standard:keep`、`standard:wait`、または `skill:<skill_id>`。基本攻撃は主系統側の `skill:normal_physical_attack` または `skill:normal_magic_attack`。旧 `standard:cut` は互換用に限定し、通常候補に生成しない。
- `name`, `description`: 表示名と説明。
- `command_group`: 所属コマンド。
- `source_type`: `standard` または `skill`。
- `usable`, `reason`: 現在使用可能かと使用不可理由。
- `target_type`, `min_range`, `max_range`: 対象種別と射程。
- `resource_type`, `resource_cost`, `cooldown`: 表示用の消費・クールタイム。
- `display_order`, `usable_after_move`: CSVまたは標準行動定義から得た表示順と移動後使用可否。

`MatchGame.action_candidates(char_id, command_group)` は、移動・ボール・待機の標準候補と、対象キャラクターの習得スキルから同じ `command_group` の候補を返す。攻撃は系統なし標準攻撃を追加せず、主系統側の基本攻撃を必ず候補に加える。ボール候補は通常パス、ボールキープと同分類の習得スキルを返し、通常カットは返さない。実行は既存の通常移動、パス、キープ、待機、または `use_skill()` の共通処理へ接続する。

### `ActionResult`

行動成功、メッセージ、ダメージ、回復、ボール移動、得点、行動終了有無と、演出用 `details` を保持する。

`details` には必要に応じて以下が入る。

- 行動名、行動者、対象。
- 移動経路。
- 行動側・防御側の2能力名、各値、合計、出目、補正、最終値。
- 属性、属性相性、属性ダイス。
- 成功・失敗。
- 消費リソース、ダメージ、回復、位置変更。
- 攻撃系統、技威力、攻撃値、防御値、能力差、能力差倍率、能力差補正、基本・最終ダメージ、軽減内容。
- カット値、保持値、各補正、成功率、1～100の乱数、最終保持者。
- パス系統、射程、距離補正、パス値、全パスカット候補、判定順、候補ごとの成功率・乱数・結果、最終保持者。
- 遠距離撃破時の攻撃距離、変更前後の保持者、ドロップ理由、ボール落下位置。
- 共通スキルID、分類、MP消費、クールタイム、使用回数、効果順ごとの処理結果。

## 6. 行動順とターン周期

1. ラウンド開始時に盤面上の行動可能ユニットを抽出。
2. 素早さの降順で並べる。
3. 同値は既存乱数で順番を決め、そのラウンド中は固定。
4. 各ユニットの行動開始時にMPを獲得。
5. 通常は+1、ボール保持中は合計+2。最大MPを超えない。
6. 全員の行動後に次のターン周期へ進む。

戦闘不能ユニットは行動順へ含まれない。行動順の一巡では通常試合を終了せず、キャラクター位置、ボール、HP、MP、状態を維持したまま次周期へ進む。`max_rounds` は旧データ読込の互換項目で、現在の終了条件には使用しない。

ボール保持状態は行動順から除外する条件ではない。盤面上の生存・行動可能キャラクターは、ボール保持者・非保持者とも行動順へ登録する。未行動者がパスを受けても通常の順番で行動し、行動済み者が受けても追加行動は発生しない。

`turn_limit` が1以上の場合は、その周期の全員が行動した時点で終了する。終了時の得点が高いチームを勝者とし、同点なら引き分け。自由試合設定画面から変更できる。クエスト試合は `match_rules.csv` の設定を使用する。

画面上部の行動順アイコンは `MatchGame.turn_order` を直接参照し、別計算を行わない。

## 7. 移動、味方通過、ZOC

`movement_paths()` が移動可能な終点と実際の経路をBFSで返す。`reachable_positions()` はその終点集合。

実効移動力は `move_range` を基準にスピード段階を適用する。標準設定ではスピード8以上が+1、3以下が-1、4～7は補正なし。閾値と補正量は `match_settings.csv` で変更する。

- 上下左右の4方向移動。
- 味方ユニットのマスは通過可能。
- 味方ユニットのマスでは停止不可。
- 敵ユニットのマスは通過・停止不可。
- 敵の上下左右がZOC。
- ZOCへ進入した時点で、その経路の移動を終了。
- 移動開始地点がZOCでも移動開始可能。
- 戦闘不能・盤面外の敵はZOCを発生させない。
- 盗賊の「影渡り」移動だけZOCを無視。

UIでは通常移動可能マスを緑、ZOCで停止するマスを橙、影渡り移動を紫、通過可能な味方マスを水色枠で表示する。

UIの移動は `prepare_move()` → 経路演出 → `arrive_prepared_move()` の順で処理する。演出中は確定位置、ボール保持、得点を変更しない。到着後は `PendingMove` に移動前の必要最小限の状態を保持し、主行動時の `commit_pending_move()` で確定する。`cancel_pending_move()` は位置、行動状態、ボール状態を復元する。

ボール保持者がゴール奥側を移動先に選んだ場合も経路を途中で切り詰めず、選択した終点まで表示位置だけを1マスずつ進める。到着時にキャラクター位置とボール位置を一度だけ反映し、その確定位置で共通得点判定を一度だけ実行する。得点時は移動経路を再演出せず、移動取消や得点後の主行動選択へ進まない。得点しなかった場合だけ通常の仮移動として主行動選択へ進む。

`move_character()` は、演出を持たないテスト・ヘッドレス実行用の即時互換APIとして上記3段階を連続実行する。

## 8. コマンド所属と移動後使用可否

画面上の基本コマンドは、攻撃、移動、ボール、スキル、待機の5種類。独立した「パス」ボタンは表示しない。各コマンドから `MatchGame.action_candidates()` を呼び、現在行動中のキャラクターが使用できる通常行動と習得スキルを取得する。

所属コマンド:

```text
attack  攻撃
move    移動
ball    ボール
skill   スキル
wait    待機
```

標準行動:

- 攻撃: 主系統に応じた物理基本攻撃または魔法基本攻撃へ接続。系統なし通常攻撃は候補外。
- 移動: `standard:move`。既存の移動可能範囲、経路演出、仮移動、移動キャンセルへ接続。
- ボール: `standard:pass`、`standard:keep`、`standard:cut`。通常パスは固定主系統を自動使用し、パス経路、パスカット候補、パス実行へ接続。キープとカットは既存処理を再利用する。
- 待機: `standard:wait`。既存の待機処理へ接続。

スキルCSVの初期分類:

- `attack`: `normal_physical_attack`、`normal_magic_attack`、`push_strike`、`elemental_bolt`。
- `move`: `shadow_step`、`breakthrough`。
- `ball`: `quick_pass`、`pass_cut`、`steal`。
- `wait`: `shield_guard`。
- `skill`: `power_up`、`heal`、`heal_hp`、`recover_mp`。

単一効果スキルの追加分類:

- `attack`: `single_physical_impact`。
- `ball`: `single_technique_long_pass`。
- `wait`: `single_stamina_guard`。
- `skill`: `single_physical_focus`、`single_magic_focus`、`single_magic_cycle`、`single_power_charge`、`single_power_push`、`single_speed_boost`、`single_speed_slow`、`single_technique_focus`、`single_stamina_recover`。

候補数によるUI挙動:

- 使用可能候補0件: コマンドボタンを使用不可にし、代表の使用不可理由を表示する。
- 候補1件: 待機が通常待機1件だけの場合は直接実行する。それ以外は名称、分類、消費、射程、移動後可否を確認できる共通行動一覧を表示する。
- 候補2件以上: 共通の行動一覧を表示する。使用不可候補も一覧へ残し、理由を表示する。

行動一覧には、行動名、通常／派生、消費MP、射程、クールタイム、移動後可否、使用不可理由を表示する。画像や専用アイコンは必須にしていない。

移動後判定は、現在の行動で `pending_move` があるかどうかを使用する。専用の `has_moved` 状態は持たない。通常移動または移動系行動の到着後、主行動で `commit_pending_move()` されるまで移動後として扱う。`cancel_pending_move()` で仮移動を取り消すと、移動後判定も解除される。

移動後の使用可否:

- `usable_after_move=true` の主行動系スキルは、その他の使用条件を満たせば移動後も使用できる。
- `usable_after_move=false` のスキルは、移動後に「移動後は使用できません」として使用不可。
- `command_group=move` の行動は、`usable_after_move` の値に関係なく移動枠使用済みなら使用不可。
- `command_group` やCSV設定に誤りがあっても、使用者自身を移動させる `action_type=movement`、突破、使用者対象の位置変更効果は移動後使用不可。
- 移動後使用不可の行動を選んでも、HP、MP、位置、ボール、行動枠、クールタイム、使用回数、一時効果は変更しない。
- 行動一覧を開いただけ、または行動を選択しただけでは仮移動を確定しない。実行直前再判定を通過し、実際に行動が開始される前にだけ仮移動を確定する。

## 9. 対抗ダイスと能力差判定

`MatchGame.contest()` は、突破や既存スティールなど明示的に対抗判定を行う特殊スキルで使用する。

```text
行動側能力 = 指定された主能力 + 副能力
防御側能力 = 指定された主能力 + 副能力
行動側 = 1～行動側能力合計の出目 + 補正 + 属性ダイス
防御側 = 1～防御側能力合計の出目 + 補正
```

- 物理・魔法の系統値と、パワー・スピード・テクニック・スタミナの基礎能力は1～10へ補正する。
- 行動側が上回れば成功。同値は防御側成功。
- 判定結果を `ActionResult.details` へ保存し、UIでは再抽選しない。
- 主系統基本攻撃、通常ダメージスキル、通常パス、攻撃由来カット／ドロップ、パスカットにはこの能力上限ダイスを使用しない。

現在も対抗ダイスを使う主な行動:

- スティール: 物理×テクニック 対 `物理×テクニック` と `魔法×テクニック` の高い方。
- 突破: 物理×パワー 対 物理×パワー。

攻撃由来のカット／ドロップとパスカットは、能力差から成功率を算出し、対象ごとに1～100の整数乱数を1回だけ生成する。乱数が最終成功率以下なら成功する。

## 10. ダメージと属性

主系統基本攻撃、押し込み攻撃、属性魔法は必中。通常の命中判定、対抗ダイス、ダメージ乱数を使用しない。突破は移動を伴う明示的対抗技能のため既存対抗判定を維持し、成功時だけ必要に応じて同じ共通ダメージ計算を使う。

物理ダメージ:

```text
攻撃値 = 攻撃者の物理 + パワー
防御値 = 防御者の物理 + スタミナ × 0.5
能力差 = 攻撃値 - 防御値
能力差割合 = clamp(能力差 × 0.05, -0.25, +0.25)
基本ダメージ = max(1, floor((技威力 + 技威力 × 能力差割合) × 0.6))
```

魔法ダメージは、上式の物理を攻撃者・防御者とも魔法へ置き換える。割合と上下限、全体倍率は `match_settings.csv` から読み込み、設定変更だけで再調整できる。

主系統基本攻撃、押し込み攻撃、属性魔法、突破成功後のダメージ、CSV共通効果方式の物理・魔法 `damage` は、すべて `damage_preview()` と `_apply_damage()` を中心とする同じ能力差計算を使用する。同じ攻撃者、対象、系統、技威力、状態なら、基本攻撃とCSV共通効果経路の基本ダメージは一致する。

CSVのdamage効果では `base_value` を技威力として使用する。`stat1`、`rate1`などの参照倍率列はデータ互換のため残しているが、系統値を技威力へ重ねて加算しない。回復やMP回復など、damage以外の効果は従来どおり参照倍率を使用する。

適用順:

1. 攻撃系統、攻撃値、防御値、能力差を決定。
2. 設定倍率から能力差補正を算出。
3. 技威力と能力差補正から基本ダメージを算出。
4. 防御コマンドの軽減。
5. シールドガードの軽減。
6. HPへ反映し、戦闘不能を確認。

明示的な完全無効化がないため、現在の最終ダメージは最低1。能力差がマイナスの場合も技威力へそのまま反映し、結果が最低値を下回った場合だけ1へ補正する。プレビューでは技威力、攻撃値、防御値、能力差、倍率、能力差補正、軽減前の基本ダメージ、現在発動可能な防御・シールドを含む予想ダメージを表示する。実行時だけシールドのMPとラウンド使用状態を消費する。

`elements.csv` の火・水・風の三すくみと属性ダイス計算ヘルパーは互換用に維持している。ただし、今回の通常ダメージ式には属性倍率・属性ダイスを適用しない。属性魔法も必中の魔法ダメージとして処理し、移動力低下効果は維持する。

## 11. 主系統基本攻撃

- ボール保持者・非保持者の両方が使用可能。保持中に攻撃しても、それだけを理由にボールを落とさず、攻撃後も同じ保持者を維持する。
- 自軍の保持・奪取・争奪状態を問わず使用可能。
- `primary_system=physical` は `normal_physical_attack`、`primary_system=magic` は `normal_magic_attack` を使用する。
- 物理基本攻撃は隣接敵、魔法基本攻撃は2マス以内の敵が対象。
- 敵の未行動、行動中、行動済み、待機中を区別せず対象にできる。
- 戦闘不能・盤面外だけを除外。
- 対象選択後、実際の物理または魔法系統、技威力、攻撃値、防御値、能力差、基本・予想ダメージを表示してから確定する。
- 命中判定なしで主系統の共通ダメージを適用する。
- 消費リソース0、必要レベル0。実行後は主行動終了。
- 系統なしの `normal_attack` は互換処理として内部に残るが、プレイヤー、AI、ヘッドレスの行動候補には追加しない。

## 12. パスとパスカット

通常パスは、試合開始時に確定した `primary_system` の物理または魔法を自動使用する。この系統を射程、パス値、全パスカット候補の計算で共通利用する。

表示名は物理主系統なら「物理パス」、魔法主系統なら「魔法パス」。プレイヤー、AI、ヘッドレスのいずれも物理・魔法を比較または手動選択せず、プレビューと実行で同じ主系統を使用する。主系統が不正な場合は物理へ補正せず使用不可にする。

```text
パス射程 = base_pass_range + (使用系統値 - 1) // 2
距離補正 = max(0, パス距離 - pass_distance_grace) × pass_distance_penalty
パス値 = テクニック + 使用系統値 // 2 + pass_power - 距離補正
```

標準設定では系統値1～2が3マス、3～4が4マス、5～6が5マス、7～8が6マス、9～10が7マス。距離はマンハッタン距離。前後左右を問わず、射程内の盤面上の味方へパスでき、行動済み・待機中の味方も受け取れる。実行後は成功・被カットを問わず主行動終了。通常パスは消費リソース0、必要レベル0。

通常パスは通常移動後も使用できる。クイックパス、ロングパスなど効果種別が `pass` の主行動スキルも `usable_after_move=true` とし、既存のMP、クールタイム、使用回数、ボール状態などの条件を満たせば通常移動後に使用できる。

移動後のパスは既存の仮移動を利用する。対象一覧とプレビューは仮移動後の位置から射程、経路、パス値、受動・反応パスカット候補を計算するが、この段階では移動を確定しない。パス対象の選択取消では主行動選択へ戻り、仮移動を維持する。「移動キャンセル」では移動前の位置とボール状態へ戻す。

パス実行時は、対象・射程・スキル使用条件とプレビューが有効であることを確認した後、MP消費と乱数判定の前に `commit_pending_move()` で仮移動を確定する。確定後の位置から通常パスとパススキル共通の `pass_ball()` を実行し、パス成功、受動・反応パスカット、得点を処理する。無効なパスでは移動、MP、クールタイム、使用回数を確定しない。移動後パスは移動枠と主行動枠を各1回使用し、結果にかかわらず主行動を終了する。この実行順は手動操作、味方オート、敵AI、ヘッドレス、ルール層の直接呼び出しで共通とする。

`pass_preview()` は、既存の直線経路、パス値、全パスカット候補、候補ごとの成功率、パス通過率を返す。

候補範囲:

- スピード1～3: パス経路上だけ。
- スピード4～7: 経路上または上下左右1マス。
- スピード8～10: 経路上または斜めを含む周囲1マス。
- 戦闘不能、盤面外、行動不能は候補外。
- 同じキャラクターは1回だけ候補になる。

```text
パスカット値 = テクニック + パスと同じ系統値 // 2 + pass_cut
能力差 = パスカット値 - パス値
成功率 = clamp(30 + 能力差 × 5 + 位置補正0 + 状態補正0, 5, 95)
```

複数候補の判定順:

1. ボールが先に到達する経路位置。
2. 同じ位置ならスピード降順。
3. 同じスピードなら現在の行動順。
4. それでも同じなら固定ID昇順。

候補者ごとに1～100を1回だけ判定し、最初の成功者がその場でボールを保持する。成功後の候補は判定しない。全員失敗または候補なしならパス対象が保持する。パスカット側の主行動済み状態は変更しない。パス通過率は全候補の失敗率を乗算した値。

クイックパスはスキルの `pass_bonus` を追加し、行動者の固定主系統を使用する同じパス処理へ接続する。

パス成功後、受け手がすでに相手ゴール上にいれば即座に得点する。ロングパスも行動者の固定主系統へ射程+1を適用し、通常パスと同じ処理を使う。

## 13. 旧通常カット互換とスティール

### 旧通常カット（互換用）

- 旧テストや互換API向けにルール層の内部関数だけを残す。プレイヤー、AI、味方オート、ヘッドレスの行動候補には生成しない。
- 上下左右に隣接する敵ボール保持者だけが対象。斜めと2マス以上は不可。
- 対象選択後に物理カットまたは魔法カットを選択する。
- 消費リソース0。成功・失敗を問わず主行動終了。

```text
カット値 = カット側テクニック + 選択系統値 // 2 + ball_cut
保持値 = 保持側テクニック + 同じ系統値 // 2 + ball_keep + キープ状態補正
能力差 = カット値 - 保持値
成功率 = clamp(45 + 能力差 × 5 + 状況補正0, 5, 95)
```

この旧計算式は通常ゲームのUIプレビューやAI評価では使用しない。現行の攻撃由来カットはスキルCSVのテクニック差設定を使う。

### スティール

- 盗賊の能動スキル。通常カットとは別処理で、共通効果方式へ移行済み。
- 物理×テクニック、消費MP2、奪取状態専用。技能レベルとスタミナは使用条件にしない。
- 隣接する敵ボール保持者が対象。
- 防御側は物理×テクニックと魔法×テクニックの高い方。
- 成功時だけ保持者を変更。ダメージなし。
- 成功・失敗にかかわらず行動終了。
- 成功・失敗にかかわらずMPと使用回数を確定し、行動終了。

### CSV共通処理へ登録した代表スキル

- `normal_physical_attack` 攻撃・物理: 射程1、MP0、必中。技威力12と、物理＋パワー対物理＋スタミナ×0.5の共通能力差計算を使用。
- `normal_magic_attack` 攻撃・魔法: 射程2、MP0、必中。技威力9と、魔法＋パワー対魔法＋スタミナ×0.5の共通能力差計算を使用。
- `power_up` パワーアップ: MP2、クールタイム2。パワー+2を自分の行動2回分付与し、再使用時は重複せず更新。
- `heal_hp` HP回復: MP3、自分または1マス以内の味方。スタミナ参照のHP回復。
- `recover_mp` MP回復: MP2、自分または2マス以内の味方、クールタイム3。魔法とスタミナ参照のMP回復。
- `pass_cut` パスカット: MP2、クールタイム1。敵パスに1回反応し、成功時は反応地点へボールを落とす。失敗時はパス継続。
- `steal` スティール: MP2。物理×テクニック対抗判定に成功すると保持者を使用者へ変更。

### 単一効果スキル12種

- `single_physical_focus` 闘気強化: MP2。物理+2を自分の行動2回分付与。
- `single_physical_impact` 衝撃打: MP2、射程1。通常の共通物理攻撃より技威力が3高い必中攻撃。同じ共通能力差計算を使用。
- `single_magic_focus` 魔力集中: MP2。魔法+2を自分の行動2回分付与。
- `single_magic_cycle` 魔力循環: 消費なし。自分のMPを2回復。
- `single_power_charge` 力溜め: MP2。パワー+2を自分の行動2回分付与。
- `single_power_push` 押し退け: MP2、射程1。ダメージなしで対象を後方へ1マス押し出す。押し出し先が盤外または占有中なら使用不可。
- `single_speed_boost` 加速: MP2。スピード+2を自分の行動2回分付与。
- `single_speed_slow` 鈍足: MP2、射程2。敵1人のスピード-2を対象の行動2回分付与。
- `single_technique_focus` 精密操作: MP2。テクニック+2を自分の行動2回分付与。
- `single_technique_long_pass` ロングパス: MP2。通常の物理／魔法パス射程を1マス伸ばしてパスする。クールタイム1。
- `single_stamina_recover` 自己回復: MP2。`3 + スタミナ` のHPを自分に回復。
- `single_stamina_guard` 防御姿勢: MP1。次の自分の行動開始まで既存の防御状態になる。

能力変更は同一スキル・同一能力の効果を重複加算せず、再使用時に値と残り回数を更新する。付与直後の行動終了では回数を減らさず、以後そのキャラクター自身の行動終了ごとに減らす。能力値の実効値は設定範囲1～10へ補正する。

反応パスカットは通常の受動パスカットとは別枠。複数の反応待機者がいる場合は、経路距離、判定能力、現在の行動順、既存乱数の順で1人だけが反応する。成功・失敗後、または次の自分の行動開始時に待機を解除する。

## 14. 5職種と代表能力

### 戦士

- 高HP、高物理・パワー、物理スキルレベル6。
- `push_strike` 押し込み攻撃: 消費なし、必中の物理ダメージ、可能なら1マス押し出し。
- `shield_guard`: 魔法×パワー、MP消費による隣接支援。

### 魔法使い

- 高MP、高魔法・パワー、魔法スキルレベル6。
- `elemental_bolt` 属性魔法: MP消費、射程3、必中の魔法ダメージ、移動力-1。属性ダイスは現在のダメージへ適用しない。

### 僧侶

- `heal` ヒール: 魔法×パワーを参照して回復。全チーム状態で使用可能。
- `shield_guard` による支援。

### 盗賊

- 高スピード・テクニック、物理／魔法スキルレベル3の複合型。
- `steal` スティール。
- `shadow_step` 影渡り: 物理×スピード、消費なし、その移動だけ敵ZOCを無視。

### 格闘家

- 高物理・パワー、物理スキルレベル6、魔法スキルレベル0。
- `breakthrough` 突破: 物理×パワー、消費なし、敵を押して元の敵マスへ進む。保持状態のHP攻撃禁止設定中は位置効果だけを適用する。

既存のクイックパスとシールドガードも維持している。クイックパスは主系統の強化パスで、通常パスと同じ共通計算・複数パスカット処理を使う。実行後は行動を終了し、追加移動は発生しない。

## 15. HP、MP、固定スタミナ、戦闘不能、得点

- HPとMPはラウンド切替で初期化しない。
- 行動開始時はMPが通常1、ボール保持中2回復する。
- スタミナは固定能力であり、行動開始、待機、スキル使用、得点で増減しない。
- HP0は戦闘不能となり、得点が入るまで盤面外。
- 戦闘不能中は行動、攻撃対象、スキル対象、ZOC発生不可。

攻撃でボール保持者が戦闘不能になった場合は、ダメージ適用前の対象位置を保存する。攻撃距離にかかわらず攻撃者へボールを移さず、通常のカット／ドロップ判定も行わない。対象の戦闘不能直前位置の周囲8マスへ強制ドロップし、結果詳細、全ログ、試合レポートに落下位置と強制ドロップであることを記録する。

得点後:

- 全員を初期配置へ戻す。
- 生存者は現在HP/MPへ最大値の50％を加算。
- 戦闘不能者は最大HP/MPの50％で復帰。
- 端数は切り上げ。
- 最大値を超えない。
- 防御、キープ、行動不能、移動低下など一時状態を解除。
- 得点演出完了後に初期配置へ戻す。
- ボール保持者を一度未設定にし、失点側から再開保持者を選ぶ。
- 得点前のAI行動案、保留中の移動計画、直近パス履歴、直近位置・目的履歴を破棄する。
- 再開後の最初の行動で所属チーム、自軍ゴール、攻撃対象ゴール、ボール状態を盤面から再取得する。
- 手動の味方が失点した場合はプレイヤー選択。敵または味方オートは、`物理×テクニック` と `魔法×テクニック` の高い方、最大HP、安定した初期順の優先順位で自動選択。
- 勝利得点の場合は保持者選択を行わず試合終了。

得点判定は通常移動だけでなく、突破、押し込み、強制移動、ZOC無視移動、パス、パスカット、攻撃由来のボール変更、スティール、ルーズボール取得、共通スキルの位置・保持者変更後と行動開始時に共通の `score_holder_in_goal()` を使用する。同一得点は再開準備または試合終了状態で再実行を防ぐ。

## 16. 行動演出と入力ロック

UIは設定時間に基づく演出キューを作る。移動については状態確定前に演出し、攻撃・カット・パスカットなどの判定については確定済みの `ActionResult` を再生する。

1. 行動者と行動名。
2. 移動経路を1マスずつ表示。
3. 対抗判定、ダメージ計算、カット、またはパスカット結果パネル。
4. 成功・失敗と結果。
5. 次の行動者。

演出中は盤面と通常行動ボタンをロックする。味方オートOFFの手動モードでは、判定結果パネルを表示した時点で時間進行を停止し、新しいクリックまたはタップを受け付けるまで閉じない。確認入力は表示を進めるだけで、判定、ダメージ、回復を再計算しない。行動確定に使用した入力は確認入力へ流用しない。敵AIの判定も手動モードでは同じ確認待ちになる。味方オートONでは既存の表示時間で自動進行する。移動の1マス表示と行動開始表示は手動でも時間進行を維持する。

結果パネル表示内容:

- 行動名、行動者、対象。
- 行動側・防御側の主能力、副能力、各値、合計、出目、補正、最終値。
- 属性名、相性、属性ダイス。
- 成功・失敗。同値は防御側と明記。
- ダメージまたは回復結果。
- 能力差ダメージでは攻撃系統、技威力、攻撃値、防御値、能力差、基本・最終ダメージ、軽減。
- 遠距離撃破ではボール落下位置。
- 手動確認待ちでは「クリックまたはタップで次へ」。
- カットではカット値、保持値、成功率、乱数、結果。
- パスでは実際に判定した候補ごとの成功率、乱数、結果。成功者以降は表示・判定しない。

時間設定は `match_settings.csv` の以下のキー。

- `action_intro_ms`
- `move_step_ms`
- `judgement_ms`
- `result_ms`

手動操作は通常速度、味方オート開始時は標準10倍。速度ボタンで通常速度と10倍を切り替えられる。既存の20倍スキップは得点までの高速確認用として独立して維持する。速度倍率は演出・メッセージ・AI待機時間だけへ適用し、乱数や試合計算には影響しない。

## 17. オートとAI

画面上部のオートボタンで味方を手動・AI操作へ切り替える。

- 敵AIと味方オートは同じ `ai_take_turn()` を使用。
- プレイヤーと同じ移動、ZOC、射程、MP、固定スタミナ能力、必要レベル、チーム状態、パス、スキル処理を呼ぶ。
- スキル使用可否はプレイヤーと同じ `can_use_skill()` を通すため、移動後使用不可をAIだけが無視することはない。
- オートは得点後も継続。
- 演出中にOFFにした場合、現在の行動完了後から手動へ戻る。
- 試合終了後はAI処理停止。
- 味方には専用AIプロフィール、調整値、保存データを適用しない。敵プロフィール値は同じ優先段階内の比較だけに使用する。
- 行動開始時に自分保持、味方保持、敵保持、ルーズボールの4状態と、パワー型、テクニック型、支援型の役割を取得する。
- 現在位置を含む全移動可能位置について、移動後に実行できる攻撃、パス、カット、スティール、回復、MP回復、強化、防御、位置取りを組み合わせた `AIActionPlan` を作成する。
- 得点、敵保持者の撃破・奪取・有効攻撃、緊急回復などの優先段階を先に比較し、同一段階だけを状況値と敵プロフィールで比較する。待機は有効候補がない場合だけ選ぶ。
- 選択した移動と主行動は一つの計画として固定する。UIの移動演出後も主行動を作り直さず、実行直前に使用可否を再確認して失敗時は残り候補を検討する。

チーム相対の方向評価:

- `target_goal_cells(team)` は攻撃対象ゴール領域、`own_goal_cells(team)` は自軍ゴール領域を返す。
- `goal_distance()` は領域内全マスへのマンハッタン距離の最小値を使用する。
- `movement_direction()` は移動前後の攻撃対象ゴール距離から `forward`、`lateral`、`backward` を返す。
- 味方は右側ゴールへ向かう方向を前進、敵は左側ゴールへ向かう方向を前進として、フィールド設定から毎行動算出する。固定したX増減判定や得点前の方向キャッシュは使用しない。
- ボール保持中は自軍ゴール侵入、利益のない後退、後退後の強化・防御・待機を候補外にする。後方パスは包囲回避、受取側の安全改善、または攻撃対象ゴールへの進展がある場合だけ許可する。
- 味方保持時の純粋な位置取りでは、保持者追従だけを理由とする後退を行わない。

敵保持者対応:

1. 敵保持者を戦闘不能にできる攻撃。
2. スティールまたは成功率の高いカット攻撃。
3. ダメージとドロップ率を含む敵保持者への有効攻撃。
4. 自軍ゴールへの進路妨害、接近、パス経路妨害。
5. 緊急回復、強化、防御。
6. 待機。

敵保持者への攻撃またはスティール計画が存在する場合、敵保持者から離れる位置取りと強化・防御候補を除外する。攻撃候補はダメージ、撃破可否、カット／ドロップ成功率、消費を比較する。共通スキルの対象選択と実行はプレイヤーと同じ `skill_targets()`、`can_use_skill()`、`use_skill()` を使用し、AI専用効果処理は持たない。

HP回復対象は最大HPに対する現在HP割合で比較する。MP回復は対象MP50％以下を開始条件とし、実回復量が最大MP25％以上、または回復後に有効スキルが使用可能になる場合だけ候補にする。同じ強化効果が有効中の再使用、敵非保持時の不要なパスカット準備、進展・安全改善のない直前相手への返しパスを候補外にする。これらの閾値と履歴件数は `match_settings.csv` で管理する。

## 18. UI

ホーム、クエスト選択、パーティー編成画面:

- 起動後はホーム画面を表示する。内部状態名は互換性のため `title` のまま維持し、表示ボタンは「クエスト」「自由試合」「終了」。
- 「クエスト」はクエスト選択画面へ遷移する。有効な `quests.csv` 行だけをCSV読込順で一覧表示し、クエスト名、説明、フィールド、フィールドサイズ、敵グループ、出場人数、対戦人数、パーティー上限、ベンチ最大人数、勝利必要得点、最大ターン、交代、負傷、推奨レベル、推奨コストを表示する。
- クエスト一覧はマウス、タップ、ホイール、上下ボタンで選択・スクロールできる。先頭の有効クエストを初期選択し、決定時に選択中クエストIDだけを編成画面へ渡す。
- クエスト用編成画面は `characters.csv` から味方を手動編成する。敵グループは選択クエストの `enemy_group_id` で固定し、敵グループ変更ボタン、敵キャラクター手動追加、敵AI変更ボタンは表示しない。
- クエスト用編成画面にはクエスト名、説明、フィールド名、フィールドサイズ、敵グループ名、出場人数、パーティー上限、現在人数、現在総コスト、総コスト上限、勝利必要得点、最大ターン、交代、負傷、最大7枠の味方編成枠の出場/控え表示を表示する。
- 自由試合は `characters.csv` の味方手動編成を基礎に、敵グループ方式と敵手動編成方式を切り替える。味方/敵とも最大7人の参加枠を持ち、敵手動編成方式では敵スロット別AI変更も維持する。
- ホームの「自由試合」は自由試合設定画面へ遷移する。クエスト選択の戻る/Escはホーム、クエスト編成の戻る/Escはクエスト選択、自由試合設定の戻る/Escはホームへ戻る。
- `characters.csv` の有効行をCSV順で一覧表示し、アイコン欠損時は文字表示へフォールバックする。
- 職種・属性フィルター、CSV順・名前順・物理・魔法・パワー・スピード・テクニック・スタミナ順を切り替えられる。
- 一覧は8件単位で表示し、上下ボタンとマウスホイールでスクロールする。
- 選択詳細にHP、MP、スタミナ、物理、魔法、パワー、スピード、テクニック、技能レベル、移動力、習得スキルを表示する。
- クエスト編成は味方枠へ、自由試合の敵手動編成方式は味方・敵枠へ空き枠順で追加する。同じチーム内だけ同じ `char_id` の重複を禁止する。味方と敵の間では同じ元キャラクターを許可し、敵側へ別の試合用IDを割り当てて状態を独立させる。
- 編成枠を選択して外す、従来の固定編成へ戻す、全解除ができる。
- HP、MP、スタミナ、物理、魔法、パワー、スピード、テクニックのチーム合計を随時比較表示する。
- 各チームの有効枠が同一チーム内重複なしで埋まった場合だけ試合開始できる。編成枠1～3を設定済み初期座標1～3へ割り当てる。
- 編成画面はマスター表示用の `RosterCharacter` のみを保持し、試合開始時に選択IDから新しい `Character` を生成する。
- キャラクター詳細の「スキル交代」から、現在のスキル枠と交換候補を選び、枠数を変えずに置換できる。
- 交換候補は、有効かつデータ検証済みの全装備スキル。標準行動の `standard:move`、`standard:pass`、`standard:wait` は装備スキルではないため候補外。
- 同じキャラクターの複数枠へ同一スキルは設定できない。「このキャラを初期化」でCSVの初期スキルへ戻す。
- 交代内容は編成中の一時データとして管理し、試合開始時に選択6人分を新しい `Character.skills` へ反映する。
- 通常編成画面には味方AI設定ボタン、プロフィール名、数値調整、保存・リセット操作を表示しない。既存の旧AI設定ファイルが残っていても編成画面と試合生成は参照しない。
- 自由試合の敵手動編成方式では、敵チームの各編成枠に `AI:プロフィール名` ボタンを表示し、敵スロットごとのAIプロフィールを循環選択できる。試合開始時は敵スロット側プロフィールがキャラクター初期AIより優先される。敵グループ方式では敵グループCSVのAI適用順を使用し、参加人数を超えるグループは開始時に拒否する。
- クエスト試合の結果画面はクエスト名を表示し、「もう一度試合」「編成へ戻る」「クエスト選択へ戻る」「ホームへ戻る」を表示する。再試合は同じクエストID、味方編成、スキル交代内容から全キャラクターを新規生成する。「編成へ戻る」は直前のクエストIDと一時編成を維持し、「ホームへ戻る」はクエスト試合の一時状態を破棄する。

自由試合:

- 旧デバッグ編成画面を基礎として拡張し、表示名は「自由試合」で統一する。内部の `party_debug_mode`、保存ファイル名、終了理由IDなどは互換性のため残す。
- 敵編成方式は「敵グループ」と「敵手動編成」。初期値は敵グループ方式だが、保存済み設定がある場合は保存値を優先する。
- 敵グループ方式では有効な `enemy_groups.csv` 候補を選択し、`create_match(enemy_group_id=...)` に接続する。手動敵IDと敵スロットAI上書きは試合生成へ渡さない。
- 敵手動編成方式では `characters.csv` から敵チームを個別編成し、既存の `create_match(player_ids, enemy_ids, ...)` に接続する。敵グループIDは渡さない。
- 味方・敵それぞれで参加人数と出場人数を1～既存上限6人の範囲で別々に変更できる。出場人数を超えた参加者は既存 `on_bench` として扱う。
- 参加人数、出場人数、現在ベンチ人数は画面上部と設定画面で確認できる。出場人数が参加人数を超える場合はUI操作でクランプする。
- 交代機能と負傷機能を自由試合設定から有効/無効にでき、試合生成時の `MatchConfig.substitution_enabled`、`injury_enabled` に渡す。
- 選択キャラクターの物理、魔法、パワー、スピード、テクニック、スタミナを1～10、最大HPを1～999、最大MPを1～99の範囲で一時変更できる。
- 敵手動編成方式では敵の各有効枠だけAIプロフィールを循環選択できる。味方は自由試合でも共通AI役割を使用し、プロフィール上書きを行わない。
- 選択した編成枠の初期X・Y座標をフィールド内で変更できる。全参加者の初期配置が重複している場合は試合開始不可。
- 先取点は1～9、ターン制限は1～99で設定できる。
- 自由試合設定画面では現在設定の保存、最後の保存設定の再読込、CSV初期設定への復帰を行える。形式バージョン3の `data/save/debug_match_last.json` へ原子的に1件保存し、画面表示時に自動読込、試合開始直前に自動保存する。
- 保存項目は、敵編成方式、選択中敵グループID、味方/敵の参加人数、出場人数、味方/敵スロット、能力上書き、敵AIプロフィール、初期配置、先取点、ターン制限、交代、負傷、スキル交代を含む。
- 形式バージョン1の旧デバッグ設定JSONも読み込む。旧形式に敵手動スロットがあれば敵手動編成方式、判定不能なら敵グループ方式として復元し、不足項目は既定値で補完する。破損JSON、不明ID、不正型は停止せず、復元できない項目だけ初期値へ戻す。
- 設定値は `config_overrides`、`character_overrides`、敵スロット別AIとして新しい試合へ渡すだけで、CSVやキャラクターマスターへ保存しない。
- 自由試合結果画面は「もう一度試合」「自由試合設定へ戻る」「ホームへ戻る」を表示する。再試合は直前の自由試合設定を使い、HP、MP、位置、負傷、一時効果、クールタイム、使用回数などの試合中状態は新規生成で初期化する。

画面上部:

- 得点、ラウンド、勝利条件、ボール保持情報、両チームの保持・奪取・争奪状態。
- 実際の `turn_order` と一致する顔アイコン。
- 味方・敵の枠色。
- 現在行動者の金枠。
- ボール保持アイコン。
- 行動済み・待機・戦闘不能表示。
- オートボタン、速度ボタン、オプションボタン。

試合画面レイアウトと背景:

- ウィンドウとゲーム内論理解像度は1440×900。フィールド表示領域は1352×520で、レイアウトの幅・高さから正方形セルサイズを自動計算し、盤面全体を表示領域中央へ配置する。13×5は従来どおり1マス104px、11×5は104px、15×7は74pxで表示される。
- 旧右側常設パネルは表示しない。フィールド下には、選択中キャラクターの名前、HP、MP、状態、ボール保持状態だけを表示する簡易情報欄を置く。
- `assets/images/backgrounds/battle_background.png` を画面全体、`battle_field.png` をフィールドへ縦横比を保ったcover方式で拡大・中央切り抜きし、読取り用の半透明シェードを重ねる。
- 背景画像は起動時に表示サイズへ変換してキャッシュする。欠損・読込失敗時は警告し、単色背景へフォールバックして試合を継続する。

盤面:

- 左右の3×3ゴール領域を既存の青・赤でグリッド背面に表示。
- 現在行動者、選択者、攻撃対象、スキル対象。
- 通常移動、ZOC停止、影渡り、味方通過表示。
- パス経路と全パスカット候補。候補は橙枠。

キャラクター付近のコマンドウィンドウ:

- 味方手動操作では、演出・判定結果確認が完了して入力可能になった時点で現在行動者を自動選択し、コマンドウィンドウを自動表示する。敵AI、味方オート、モーダル、演出、再開保持者選択中は表示しない。
- 表示状態、対象キャラクターID、表示開始入力フレーム、直近の描画矩形を明示的なUI状態として保持する。キャラクターの選択枠から毎フレーム暗黙的に開閉状態を復元しない。
- 同じ現在行動者を再度選択する処理は冪等な「開く」処理であり、タッチ由来の重複イベントでトグルして閉じない。
- 基本コマンドは攻撃、移動、ボール、スキル、待機。独立した「パス」や新規防御コマンドは追加しない。
- 各コマンドは `action_candidates()` の結果から有効／無効と理由を決める。UIだけで射程、MP、移動後可否を重複判定しない。
- 盤面のマス座標から画面矩形、画面座標からマス座標への変換は `cell_rect()`、`screen_to_cell()` が共通の盤面原点とセルサイズを使う。クリック、タップ、疑似マウス、キャラクター、ボール、移動範囲、ZOC、対象枠、パス経路は同じ変換へ接続する。
- コマンドウィンドウはキャラクターの論理画面上の矩形を基準に、右側、入らなければ左側へ置き、最終矩形をフィールド内の安全余白へクランプする。
- 表示位置は描画ごとに現在行動者の位置から再計算する。CanvasのCSS座標や回転前の端末座標を配置値へ使用しない。
- コマンドボタンで処理した入力はそこで消費し、背面フィールドへ伝播させない。ウィンドウ外のフィールドを選択した場合は閉じる。
- 現在行動者の交代、行動演出開始、オート開始、リタイア確認、全画面行動選択への遷移時は閉じる。

共通全画面行動選択:

- 攻撃、移動、ボール、スキルは候補数が1件でも、同じ全画面行動選択部品へコマンド種別と `ActionCandidate` 一覧を渡す。待機が標準待機1件だけの場合は直接確認・実行へ進む。
- 左側は簡易カテゴリ記号と行動名、右側は説明、カテゴリ、対象、射程、消費、クールタイム、ボール状態、移動後可否、参照能力、判定方式、効果順、使用不可理由を日本語で表示する。
- 使用不可候補も選択して詳細を確認できるが、決定ボタンは無効。初期選択は表示順が最初の使用可能候補、全件使用不可なら先頭候補。
- 一覧と詳細はマウスホイールおよび画面内の上下ボタンでスクロールできる。
- 選択画面中は得点、フィールド、行動順、オート、速度を表示せず、AIと演出進行を停止する。
- 決定では行動IDまたはスキルIDだけを選択し、既存の射程・対象・プレビュー・仮移動・実行処理へ戻す。対象確定までHP、MP、位置、ボール、行動枠を変更しない。
- 戻るでは試合状態を変更せずフィールドへ戻り、現在行動者のコマンドウィンドウを再表示する。
- 攻撃対象、パス対象、スキル対象の選択後は、フィールド下部右側の決定／戻るを使用する。通常カットのUI導線は表示せず、カットは攻撃コマンド内の対応スキルとして選択する。

マウス・タップ入力とpygbag:

- `MOUSEBUTTONDOWN` と `FINGERDOWN` は、入力種別、論理座標、生座標、時刻、タッチ由来、正規化座標か、消費状態を持つ共通 `PointerInput` へ変換してから同じ `handle_pointer()` へ渡す。
- `FINGERDOWN` の0～1正規化座標は1440×900のゲームSurface寸法へ変換する。描画と当たり判定は同じ論理座標を使用し、CanvasのCSS拡大率を個別UIへ適用しない。
- 1入力フレームにつきポインター操作は1件だけ処理する。タッチ直後750ms以内のマウス入力はCanvas/CSS座標差にかかわらず疑似マウスとして無視する。イベント順が逆の場合は、750ms以内かつ論理座標32px以内の異種イベントを同じ物理タップとして無視する。
- 抑制対象は異種イベントだけで、通常PCマウスの連続クリックは無効化しない。タッチを受信していないPC環境のマウス入力には抑制を適用しない。
- 入力優先順はモーダル、全画面行動選択、コマンドウィンドウ、フィールド上のキャラクター、フィールド上のマス。上位で処理した場合は即時returnし、背面へ伝播しない。
- `VIDEORESIZE` / `WINDOWSIZECHANGED` では正常な表示領域寸法を記録し、コマンド矩形だけを破棄して次の描画で再計算する。選択中キャラクターとコマンド表示状態は維持する。
- 入力診断は `manaball.ui` のDEBUGログで、イベント種別、時刻、生座標、正規化有無、論理座標、現在行動者、選択ID、コマンド状態変更、矩形、入力フレームを確認できる。通常ログレベルでは出力しない。

画面内ログ:

- 常設ログ領域は表示しない。
- 「全ログ」モーダルに試合開始から現在までのログを時系列表示する。
- 上下ボタンとマウスホイールでスクロールし、全文をクリップボードへコピーできる。
- 全ログ表示中は入力とAI進行を停止し、閉じると同じ状態から再開する。

試合バランスレポート:

- 通常、オート、デバッグ、ヘッドレスの各試合で同じ `MatchReportCollector` を使用する。実行形式は `manual`、`auto`、`headless` として記録する。
- 試合開始時にモード、乱数シード、勝利条件、参加者、初期能力、初期配置、スキル、共通AI役割、敵AIプロフィールを保存する。味方AIプロフィール・調整値欄は出力しない。
- 敵グループ使用時は敵グループID、能力倍率、各個体の敵マスターID、敵タイプID、グループ内スロット、最終AIプロフィールを開始時情報へ保存する。
- 各行動について行動前後のHP、MP、位置、ボール、得点、戦闘不能状態と、確定済みの判定結果を記録する。
- AI行動には所属チーム、ボール状態、自軍・攻撃対象ゴール、攻撃方向、移動前後のゴール距離、前進・横移動・後退、目的、敵保持者、保持者攻撃可否、強化・後退・待機理由を記録する。
- 遠距離撃破ドロップは攻撃結果の詳細として理由、攻撃者、戦闘不能者、攻撃距離、落下位置、変更前後の保持者を記録する。
- 通常移動、スキル移動、強制移動は経路、距離、移動前後位置を別々に記録する。キャンセルした仮移動は集計しない。
- ダメージは計算上ダメージ、実際に減少したHP、過剰ダメージを分離する。HP/MP回復も計算量、実回復量、過剰回復、回復原因を分離する。
- 得点、得点後再配置・回復、ターン開始MP回復、戦闘不能、試合終了をシステムイベントとして行動順に記録する。得点イベントは再配置や試合終了より先に記録する。
- 試合終了時に `log/YYYY_MM_DD_HHMMSS_NNN.md` を自動生成する。同時刻の複数試合も末尾の連番で別ファイルになる。
- レポートは「試合概要」「試合条件」「開始時キャラクター情報」「試合結果」「キャラクター別集計」「スキル別集計」「行動ログ」「試合全体集計」の8章で構成する。
- キャラクター別には移動、待機、攻撃、スキル、与被ダメージ、回復、MP消費・回復、パス、カット、スティール、得点、戦闘不能を集計する。
- スキル別には使用・成功・失敗、計算上／実ダメージ、過剰ダメージ、HP/MP回復、MP消費、平均実ダメージ、平均回復量を集計する。
- レポートは一時ファイルへUTF-8・LFで書き込み後、最終ファイルへ置換する。保存失敗は例外を試合へ伝播させず、エラーログへ記録する。

リタイアと結果:

- 試合画面の「リタイア」は行動演出中と試合終了後は使用不可。押すと確認モーダルを表示し、背面の入力とAI進行を停止する。
- 通常試合で味方がリタイアすると敵勝利、終了理由 `retire`。自由試合では勝敗なし、終了理由 `debug_interrupt`。
- ターン制限終了は `turn_limit`、勝利得点到達は `score`。`result_summary()` は勝者、引き分け、終了理由、モード、得点、ラウンド、各種行動統計を返す。
- 結果画面は終了理由に応じて「リタイア敗北」「デバッグ中断」などを区別して表示する。
- クエスト試合ではクエスト名を表示する。「もう一度試合」は同じクエストID、味方編成、スキル設定から全員を新規生成し、「編成へ戻る」は直前の一時編成を維持する。自由試合では「自由試合設定へ戻る」と「ホームへ戻る」を表示する。

## 19. エラー処理と互換性

- 旧キャラクターCSVに新能力、スタミナ、技能レベル列がない場合、近い旧能力または安全な既定値を使用して警告。`stamina` 列がない場合は旧 `max_stamina` 列を固定スタミナとして読み込む。
- 職種不明は「職種なし」。
- 属性不明は「無属性」。
- 物理・魔法の系統値と、パワー・スピード・テクニックの基礎能力は設定範囲へ、技能レベルは0～6へ補正して警告。
- 最大HP、最大MPが0以下なら最低1へ補正。スタミナは他の基礎能力と同じ設定範囲へ補正。
- スキル系統、タイプ、状態、リソース、行動側能力が不正ならスキル単位で使用不可。
- スキルCSVに `command_group`、`usable_after_move`、`display_order` がない場合は、安全な既定値へ補完する。
- `command_group` が空の場合は、既存の `action_type` と `purpose_tag` から攻撃、移動、ボール、待機、スキルのいずれかへ補完して警告する。
- 旧 `command_group=pass` は読込互換として警告付きで `ball` へ変換する。新規データの正式値には使用しない。
- `command_group` が不正値の場合は、そのスキルをデータ不正として使用不可にし、内部値は安全な `skill` へ補正する。
- `usable_after_move` が空または列なしの場合は `true`。不正値の場合も `true` へ補完して警告する。
- `display_order` が空の場合はCSV読込順を使用する。不正値の場合は安全な既定値へ補完して警告する。
- 対抗スキルの防御側能力が空の場合は行動側と同じ組み合わせを使用。
- 画像欠損は色付き円と文字。
- 属性・職種アイコンは必須にせず文字表示。
- フォント欠損時はシステム日本語フォントを試す。
- MP・技能レベル・チーム状態などの条件を満たさない操作では、HP、MP、ボール、行動回数を変更しない。
- AIが候補を得られない場合は待機。
- ボール保持不整合はルーズボールへ補正して警告。
- 遠距離撃破時に戦闘不能直前位置を取得できない場合は既定のボール位置へ落とし、エラーを記録して試合を継続する。
- カット・ボールキープ・パス・パスカット補正が未設定なら0。
- 成功率設定が不正なら安全な既定値へ補正して警告。
- 基本パス射程が0以下なら安全な既定値へ補正する。
- パス経路を取得できない場合は、ボールと行動状態を変更せず実行不可。
- 共通スキルの効果数0件・6件以上、効果順重複、未実装効果、負数、能力名・発動形式・分類不正は、そのスキルだけを使用不可にして警告する。
- `force_move` は正の移動距離と空欄または `away`、`pass` は正の射程加算を必須とする。条件を満たさない効果データは使用不可。
- スキルの旧 `resource_type=stamina` は警告して `none`、消費0へ移行する。現在有効なリソース指定は `mana` と `none` だけ。
- 対象不正、射程外、MP不足、クールタイム、使用回数上限ではHP、MP、位置、ボール、一時効果、使用回数、行動状態を変更しない。
- 移動後使用不可の行動を選んだ場合も、HP、MP、位置、ボール、一時効果、クールタイム、使用回数、移動枠、主行動枠を変更しない。仮移動も確定しない。
- 共通効果実行中の予期しない例外は、実行前の必要状態へロールバックしてエラーを記録する。
- 編成人数不足、重複ID、不明IDでは試合を生成せず、編成画面の状態を維持して理由を表示する。
- 初期編成に不明IDまたは重複IDがある場合は該当枠だけ空にし、試合開始を無効にする。
- フィールド幅・高さ0以下、ゴールのフィールド外、左右ゴール重複は補正せず試合生成を中断する。
- 初期配置のフィールド外、重複、ゴール領域内は対象キャラクターと座標を含むエラーで試合生成を中断する。
- `primary_system` が未設定または不正なキャラクターは物理へ自動固定せず、攻撃とパスを使用不可にして理由を表示・記録する。
- 主系統側の基本攻撃データがない場合は系統なし攻撃へフォールバックせず、攻撃を使用不可にする。
- 交代後スキルに不明・無効・データ不正・重複IDがある場合は試合生成を中断して理由を表示する。
- `ai_profiles.csv` がない場合は組み込みの標準AIのみで起動する。
- AIプロフィールID未設定または存在しないIDは標準AIへフォールバックし、警告ログを出す。
- AIプロフィール値が空または数値変換不能なら5、0未満なら0、10超過なら10へ補正する。AIレベルは空または変換不能なら5、1未満なら1、10超過なら10へ補正する。
- AIプロフィールID重複は警告し、先に読んだ1件を採用して後続行を無視する。
- 敵グループIDの空欄・不存在・無効、グループ内の敵ID不存在・無効、敵マスター検証エラーでは試合を生成しない。
- 敵マスターの主系統不正、スキルID不存在・無効・重複・標準行動指定・技能レベル不足では、その敵を含むグループの試合を生成しない。
- 敵グループ倍率の数値変換不能、0以下、NaN、無限値では試合を生成しない。空欄は1.0。
- 敵マスターまたはグループのAIプロフィールIDが未登録の場合は警告し、優先順位上の直前の有効プロフィールへフォールバックする。
- 敵マスターCSVまたは敵グループCSVが存在しない場合、クエスト編成と自由試合の敵グループ方式は利用可能グループなしとして開始を無効にする。既存の敵ID指定APIと自由試合の敵手動編成方式は起動できる。
- 旧キャラクターCSVに `default_ai_profile_id` がない場合は標準AIを使用する。
- 旧 `data/save/player_ai_settings.json` が存在しても読み込まず、通常試合、再試合、自由試合へ適用しない。新規保存処理も持たない。
- 所属チームまたは左右ゴールを取得できず攻撃方向が確定しない場合は、警告を記録して現在位置の安全な待機だけを候補にする。
- AI行動案の作成・実行中の予期しない例外は試合全体へ伝播させず、残り候補または待機へフォールバックする。
- 自由試合の出場人数が既存上限外、出場人数分のID・配置不足、初期配置重複、フィールド外配置、不正な設定上書きでは試合を生成しない。未使用の敵方式側の不足は開始エラーにしない。

## 21. 攻撃スキルとボール争奪の統合

2026-07-10に、独立していた全キャラクター共通の通常カットを通常ゲームの行動候補から廃止し、攻撃スキルのダメージ後にボール追加効果を解決する方式へ変更した。

### 基本処理

- 攻撃開始時に対象がボール保持者だった場合だけ、ダメージ確定後にボール追加効果を処理する。
- 効果種別は `none`、`drop`、`cut` の3種類。1スキルに設定できるのは1種類だけ。
- `drop` は攻撃者と保持者の現在の実効パワー差で成功率を計算する。成功時は攻撃者が取得せず、ルーズボールにする。
- `cut` は攻撃者と保持者の現在の実効テクニック差で成功率を計算する。成功時は攻撃者が直接取得する。カット効果を持つ攻撃は射程1に限定する。
- 最終成功率は `基礎成功率 + 能力差 × 差1あたり補正`をスキル別の下限・上限へ補正する。
- プレビューは乱数を生成しない。実行時は試合用 `rng`から1～100を1回だけ抽選し、確定結果を `ActionResult.details["ball_effect"]` へ保存する。
- UI、AI、全ログ、試合バランスレポートは確定済みの値を参照し、再計算や再抽選を行わない。

### CSV定義

`data/csv/skills.csv` は以下の列を持つ。列がない旧CSVや空欄はボール効果なしとして読み込む。

- `ball_effect_type`
- `ball_effect_base_rate`
- `ball_effect_actor_stat`
- `ball_effect_defender_stat`
- `ball_effect_rate_per_diff`
- `ball_effect_min_rate`
- `ball_effect_max_rate`

未対応の効果種別、能力名不正、下限が上限を超える設定、射程2以上の `cut` は警告後にボール効果だけを無効化する。数値は0～100へ補正する。

初期データ（主要な現行値）:

- `normal_physical_attack`: `drop`、基礎20%、パワー差、下限15%、上限25%。
- `normal_magic_attack`: `drop`、基礎20%、パワー差、下限15%、上限25%。
- `push_strike`: `drop`、基礎25%、パワー差、上限85%。
- `elemental_bolt`: `drop`、基礎5%、パワー差、上限50%。
- `single_physical_impact`: `drop`、基礎20%、パワー差、上限80%。
- `single_technique_ball_cut`（ボールカット攻撃）: 射程1、MP2、物理技威力7、`cut`、基礎45%、テクニック差、下限35%、上限55%。`skill_effects.csv` の共通ダメージ効果を使う。

`single_technique_ball_cut` は既存のスティール所持者である盗賊系確認キャラクターへ、既存スキルを削除せず追加している。

### 戦闘不能とルーズボール

- 攻撃対象の保持者が戦闘不能になった場合は通常の `cut` / `drop` 判定を行わず、攻撃距離にかかわらず強制ドロップする。
- 攻撃者へ直接移動せず、戦闘不能直前の位置の周囲8マスから、盤面内、非ブロック、戦闘可能キャラクター不在のセルを候補とする。
- 複数候補は試合用 `rng` で選ぶ。周囲に候補がない場合は距離と座標で安定ソートした最寄りの有効セルを使う。盤面全体に配置先がない場合は例外で試合を停止せず、戦闘不能前の位置を安全フォールバックとする。

### 基本攻撃、スティール、パスカット

- 物理主系統は `normal_physical_attack`、魔法主系統は `normal_magic_attack` を基本攻撃候補とする。
- 系統なしの旧 `normal_attack` はCSV行と互換関数を残すが `enabled=false` とし、プレイヤー、AI、ヘッドレスの候補には追加しない。
- 旧通常カットの内部関数と `ball_cut` / `ball_keep` データは互換用として残すが、通常ゲームのボールコマンド、AI計画、ヘッドレス候補には出さない。
- スティールはMPを消費するダメージなしの直接奪取スキルとして既存の対抗判定を維持する。
- 通常の受動パスカットと反応スキル `pass_cut` は、パス経路、候補順、反応待機、失敗後のパス継続を含め既存処理を維持する。

### AI、UI、ログ、レポート

- AIの攻撃評価は予想ダメージ、撃破可否、対象が保持者か、ボール効果の最終成功率、消費MPを参照する。直接取得の `cut` は `drop` より成功率の価値を高く評価する。
- 攻撃プレビューは攻撃系統、技威力、予想ダメージに加え、保持者へのボール効果種別、参照能力、攻守値、基礎率、差補正、最終率を表示する。非保持者では「対象が保持者の場合のみ」と表示する。
- 判定結果パネルは効果種別、攻守能力値、基礎率、能力差、補正、最終率、乱数、成否、強制ドロップ、落下位置を確定結果から表示する。
- 試合ログはスキル名、効果、基礎率、能力差、最終率、乱数、成否を記録する。
- Markdown試合バランスレポートは `ball_effect` 詳細と、攻撃由来のドロップ判定・成功数、カット判定・成功数、戦闘不能強制ドロップ数を出力する。

## 26. 5能力CSVと試合ログ出力区分

### 正式なキャラクター能力

- 正式能力は `power`、`magic`、`speed`、`technique`、`stamina` の5種類。
- 物理攻撃は実効パワー、魔法攻撃は実効マジック、防御は実効スタミナを使用する。旧physical、固定主系統、物理・魔法技能レベルは正規CSVと戦闘計算では使用しない。
- パワーパスは `technique * 2 + power`、マジックパスは `technique * 2 + magic` を基準とし、パスカットも受けるパスと同じ補助能力を使用する。
- ボールキープはテクニックとスタミナ、接触型カット／スティールはテクニックとパワーを中心に計算する。
- 最大HPはスタミナ、最大MPはマジックの設定係数による補正を基礎値へ加える。係数は `match_settings.csv` で管理する。

### `characters.csv`

正式な16列は次のとおり。

```text

skill_slot_1,skill_slot_2,skill_slot_3,skill_slot_4,skill_slot_5,skill_slot_6,skill_slot_7
```

- キャラクター画像は従来どおり `char_id` から解決する。

- `data/csv/classes.csv` と `data/csv/elements.csv` は削除済み。

### 試合レポート出力方針

- `play`: UIから開始した通常プレイ。`log/play/` へMarkdownを保存する。
- `ci`: `create_match(report_policy="ci")` または `--log-policy ci` で明示した試合。`log/ci/` へ保存する。
- `test`: 単体テスト、UIテスト、スモーク、通常のローカルヘッドレス。ファイルは保存しない。
- 手動、オート、ヘッドレスという実行形式と、上記の保存方針は独立して管理する。
- どの方針でもイベント収集、集計、全ログ、Markdown本文生成を行う。非保存時の本文は `game.report.markdown` から取得できる。
- `create_match()` の既定はテストによる意図しない永続保存を防ぐため `test`。通常UIは試合開始時に `play` を明示する。
- CLIヘッドレスは既定で非保存。CI保存が必要な場合は `python main.py --headless-sim --log-policy ci ...` を使用する。
- 保存先作成または書込みに失敗しても試合結果処理は継続し、通常プレイ用保存先へ誤ってフォールバックしない。

## 29. AIプロフィール再設計とボール状態別共通AI

この節は2026-07-12時点のAI、自由試合AI設定、操作方式選択、AIログに関する正規仕様である。前節までの記述と矛盾する場合は、この節と実装コード、正式CSVを優先する。

### AIプロフィールとAIレベル

`data/csv/ai_profiles.csv` は以下の正式列を使用する。

```text
ai_profile_id, ai_profile_name, description,
attack_priority, pass_priority, score_priority, heal_priority,
support_priority, steal_priority, ball_keep_priority,
loose_ball_priority, ally_guard_priority, own_goal_defense_priority,
mp_usage, risk_tolerance, enabled, notes
```

- 12種類のプロフィール値は0～10の整数で、5が標準。
- `risk_tolerance` を除き、主分類に対応する値0はその候補を原則除外する。
- `mp_usage=0` はMP消費候補を除外する。消費なしの通常行動には適用しない。
- `risk_tolerance=0` は禁止ではなく安全性を最大限重視する。
- プロフィール補正は主AI項目を1つ選び、5を1.0倍相当とする。MP補正と危険補正は別に保持する。
- 待機は専用固定評価を使用し、プロフィール、MP、危険補正を適用しない。
- 初期プロフィールは `standard`、`attack`、`pass`、`score`、`healer`、`steal`、`defense`。
- 旧AI列を検出した場合は自動変換せず、警告して組み込み標準プロフィールへフォールバックする。

AIレベルはプロフィールと分離した1～10の整数で、標準値は5。プロフィールは「何を好むか」、AIレベルは「合法候補をどの程度正確に比較するか」を表す。

- レベル10: 最高評価候補。
- レベル8～9: 上位2候補。
- レベル6～7: 上位3候補。
- レベル4～5: 上位半分、最大5候補。
- レベル2～3: 合法候補全体から評価値に応じて選択。
- レベル1: 合法候補全体から均等に近い選択。
- 選択乱数は試合用乱数を使い、同じシードと状態では再現可能。
- AIレベルが低くてもMP不足、射程外、対象不正などの不正行動は候補へ含めない。

### 敵AI設定の適用順

プロフィールとAIレベルはそれぞれ次の順で解決する。空欄は直前の有効設定を維持する。

1. 標準プロフィール／標準AIレベル5。
2. 敵マスターの `default_ai_profile_id`／`default_ai_level`。
3. 敵グループの `group_ai_profile_id`／`group_ai_level`。
4. `enemy_1`～`enemy_7` のスロット別プロフィール／AIレベル。

試合中の `Character` は、解決済みの `ai_profile_id`、`ai_profile_name`、`ai_level`、`ai_settings`、`ai_profile_source` を保持する。決定元は `character`、`enemy_master`、`enemy_group`、`enemy_slot`、`role_mapping`、`fallback` のいずれか。

### 味方オートへのプロフィール適用

味方オートと敵AIは同じ `_build_ai_plans()`、プロフィール補正、AIレベル選択、既存行動実行メソッドを使用する。味方に直接プロフィールがない場合は、既存AI役割から次のプロフィールを解決する。

- パワー型: `attack`。
- 支援型: `healer`。
- テクニック型: `steal`。
- 不明またはプロフィール欠損: `standard`。

味方の個別プロフィールを編集・保存する画面は実装しない。味方AIレベルの個別指定がない場合は5を使用する。

### ボール状態別の共通候補評価

候補生成開始時に、行動者から見た状態を `loose_ball`、`self_possession`、`ally_possession`、`enemy_possession` の4種類で固定する。移動や取得後に状態が変わっても、判断開始時状態は変更しない。

候補の最終評価は以下で構成する。

```text
基本評価
+ ボール状況補正
+ AIプロフィール補正
+ MP使用補正
+ 危険許容補正
= 最終評価
```

- ルーズボール時は各チーム1人の回収担当者を決定する。
- 回収適性は到達可能性、マンハッタン距離、スピード、テクニック、`loose_ball_priority`、現在HPから決定し、同点処理も固定順で再現可能にする。
- 担当者は同じルーズボール位置の間は維持する。戦闘不能、盤外、保持者決定、ボール位置変更時は再計算する。
- 担当者の直接取得と接近を強く加点し、無関係な攻撃を減点する。
- 担当者以外の直接取得候補は除外し、護衛、取得後の受け位置、敵回収担当者の妨害、自軍ゴール守備を評価する。
- 自分保持時は即時得点、ゴール前進、有効なパス、安全保持を無関係な攻撃より高く評価する。
- 味方保持時は受け位置、保持者護衛、前方展開、回復・支援を評価し、保持者と無関係な攻撃を減点する。
- 敵保持時はスティール、ボールカット、ボールドロップを伴う保持者攻撃、保持者への通常攻撃、進路・パス経路妨害を評価する。
- 敵保持者以外への攻撃は、撃破などの明確な価値がない場合に状況減点を受ける。
- 攻撃候補は `holder_attack`、`holder_kill`、`normal_attack`、`kill_attack` など、ボール関与と目的を区別する。
- 支援型の位置評価は敵から離れることだけを目的にせず、味方保持者または回復が必要な味方との距離を考慮する。味方から離れる後退には追加減点する。

AIプロフィールはダメージ、回復量、成功率、移動力、消費MPなどのルール計算を変更せず、合法候補の選択だけへ影響する。

### 自由試合の敵AI設定

敵手動編成方式では、敵が設定された各有効枠に `AI:プロフィール名` と `Lv:数値` の循環ボタンを表示する。

- プロフィールボタンとAIレベルボタンは編成枠内に横並びで表示する。
- 子ボタンの入力判定を編成枠本体より優先し、処理後は同じクリック／タップを背面へ渡さない。
- 描画と入力判定は同じ `Button.rect` を使用する。
- 空枠と敵グループ方式では個別変更できない。
- 変更値は自由試合一時設定だけへ保存し、敵マスターCSVへ書き戻さない。
- 保存形式はVersion 3。Version 1、2も読込可能で、AIレベル欠落時は5を補完する。
- 各敵スロットは `ai_profile_id` と `enemy_ai_level` を保存・復元する。

### 試合開始時の操作方式モーダル

新しい試合では、手動操作またはAI操作を選ぶモーダルを試合画面の最後に描画し、視覚・入力の両方で最前面にする。

- `control_mode_selected` と `show_control_mode_modal` で試合単位の選択状態を管理する。
- 表示中はモーダル専用ボタン以外のフィールド、キャラクター、コマンド、背面ボタン入力を停止する。
- モーダル外クリック、タップ、Escapeも消費し、モーダルは閉じない。
- 手動またはAIを選択した入力は背面へ伝播させない。
- 同じ試合ではラウンド更新、移動キャンセル、対象選択から戻る操作で再表示しない。
- 再試合を含む新しい `MatchGame` の開始時だけ未選択へ戻す。
- PC、Web、スマートフォンは共通ポインター入力とタッチ由来マウス入力の重複抑止を使用する。

### AI判断ログとMarkdownレポート

全ログはAI判断を複数行へ分離して表示する。

- 行動者、プロフィールID・名称、AIレベル。
- 判断開始時ボール状態と行動後ボール状態。
- ルーズボール担当者とチーム内役割。

Markdownレポートは敵AI設定を敵ごとの見出しに分け、12項目とAIレベルを日本語名で表示する。各AI行動には上位5候補の比較表を表示し、選択候補が上位5件外なら追加する。候補表には順位、行動名、目的、対象名、移動先、基本評価、ボール状況補正、チーム役割、主AI項目、プロフィール補正、MP補正、危険補正、最終評価、選択有無を含む。

`ai_candidates=[{...}]` のようなPython辞書・リスト表現は通常の判定詳細へ直接連結しない。機械解析用の候補データは行動記録内に保持し、Markdown表示時に再計算せず整形する。

### エラー処理と確認済み範囲

- AIプロフィールCSV欠損時は組み込み標準型で継続する。
- 値の空欄・変換不能は5、範囲外は0～10へ補正する。

- AIプロフィール、AIレベル、上書き順、優先度0、待機補正、味方役割マッピング、回収担当、判断開始状態、Markdown候補表の自動テストを実装済み。
- スモーク、敵グループ指定ヘッドレス、30シード連続試合を完走済み。30シード確認ではエラー0、パスとスティール、両チームの得点を確認済み。

## 30. スキル枠分離とボール状態に依存しない攻撃

この節は2026-07-12時点の装備スキル枠、基本攻撃、一般攻撃スキルの正規仕様である。前節までの記述と矛盾する場合は、この節と実装コード、正式CSVを優先する。

### 共通スキル枠

- 全味方・敵キャラクターは、通常スキル基礎枠6とボール保持スキル基礎枠1を共通で持つ。キャラクターごとの個別基礎枠数は持たない。
- 試合用 `Character` は、通常スキルとボール保持スキルについて基礎枠数と現在枠数を別々に保持する。現時点では基礎枠数と現在枠数は同じで、育成・装備・クエスト・戦闘効果による増減は未実装。
- 通常スキル枠はアクティブ、パッシブ、反応待機型で共用する。発動形式ごとの個数制限は設けない。
- ボール保持スキルは通常枠と分離し、保持中に自動発動する既存パッシブを専用枠へ分類する。将来の手動発動型も同じ専用枠を使用する。
- `skills.csv` の `equip_slot` は `normal` または `ball_hold`。装備枠区分は `activation`、`command_group`、`allowed_state`、ボール保持中の使用可否とは独立した情報である。
- `equip_slot` が空欄の旧データは、既存のボール保持スキル識別条件を満たす場合だけ `ball_hold`、それ以外は `normal` として警告付きで互換分類する。不正値のスキルは使用不可。
- 装備内容は同一IDの重複、存在しない・無効なスキル、通常6件超過、ボール保持1件超過を試合生成前に検証する。超過分を無言で削除しない。
- `characters.csv` は既存の `skill_slot_1`～`skill_slot_7` を維持する。番号で枠種別を固定せず、各スキルの `equip_slot` から分類する。
- `enemies.csv` も `skill_slot_1`～`skill_slot_7` を持ち、敵IDごとの装備内容を使用する。敵グループは従来どおり敵IDだけを指定する。
- 編成画面は「通常スキル 使用数 / 6」と「ボール保持 使用数 / 1」を分けて表示し、選択枠と同じ区分のスキルだけを交換候補にする。同一スキルの重複交換は不可。
- 自由試合の一時装備、再読込、再試合も同じ7要素の装備データと共通検証を利用し、マスターCSV自体は変更しない。

### 標準行動と基本攻撃

- 基本攻撃、通常移動、通常パス、ボールキープ、待機は装備スキル枠を消費しない標準行動。
- ボールカット攻撃、スティール、パスカット、クイックパス、ロングパスなどは通常スキル枠を使用する。
- 全キャラクター共通の旧通常カットは行動候補へ復活させない。
- 基本攻撃の計算・表示データは `skills.csv` の `normal_physical_attack` / `normal_magic_attack` を利用するが、実行時の装備スキル一覧からは除外する。
- 基本攻撃IDは固定主系統の互換情報から決定する。主系統情報がない場合は、現在のパワーとマジックを比較し、マジックが高ければ魔法、それ以外は物理を使用する。
- 基本攻撃データが存在しない、無効、または検証エラーの場合は基本攻撃だけを候補に追加せず、他の正常な装備攻撃スキルは候補へ残す。
- UIとAIは同じ `action_candidates()`、`can_use_skill()`、対象取得、攻撃実行処理を利用する。

### ボール状態に依存しない攻撃可否

- 通常攻撃と一般的な攻撃スキルの使用可否は、攻撃者、対象、第三者、チーム全体のボール保持状態から独立して判定する。
- 次の全状態で、射程、MP、クールタイム、使用回数、移動後条件などを満たせば攻撃できる。
  - 攻撃者が保持者で対象が非保持者。
  - 攻撃者が非保持者で対象が保持者。
  - 攻撃者と対象が両方非保持者で、別の味方が保持者。
  - 攻撃者と対象が両方非保持者で、別の敵が保持者。
  - ボールがルーズ状態。
  - テスト等で保持者もルーズ位置も設定されていない状態。
- 一般攻撃ではチーム状態の `possession`、`acquisition`、`contest` を共通使用禁止条件にしない。「味方保持中」「対象が非保持者」などを理由に攻撃候補を除外しない。
- スティール、ボール保持専用スキル、パスなど、目的上ボール状態を必要とする攻撃以外の行動には、既存の `allowed_states`、`usable_with_ball`、`usable_without_ball` を引き続き適用する。
- 攻撃コマンドの有効表示は、ルール層が返した使用可能な攻撃候補を基準にする。UI専用の保持者判定は持たない。
- 移動後も `usable_after_move` が真の攻撃は同じ候補生成を使う。移動後不可のスキルは保持状態ではなく移動後条件を理由として使用不可にする。

### 攻撃後のボール処理

- 攻撃の使用可否と、攻撃結果に伴うボール追加効果は別々に判定する。
- 攻撃対象が現在のボール保持者である場合だけ、攻撃由来ドロップ、ボールカット、戦闘不能時の強制ドロップ、保持スキル解除、保持者変更を既存処理へ接続する。
- 攻撃対象が非保持者の場合、上記の保持者向け処理を実行しない。第三者が保持しているボールの保持者情報も変更しない。
- 攻撃者自身が保持者で対象が非保持者の場合、攻撃したことだけを理由にボールを落とさず、攻撃後も同じ保持者を維持する。
- 攻撃失敗、射程外、MP不足、クールタイム、使用回数超過、移動後使用不可では、HP、MP、位置、行動状態、クールタイム、使用回数、ボール保持者を変更しない。

### 確認済み範囲

- ブリギッドの基本攻撃と押し込み攻撃について、保持者本人、対象保持、味方第三者保持、敵第三者保持、ルーズ、保持者なしの6状態で候補生成と対象取得を確認済み。
- 味方第三者保持中の非保持者同士の基本攻撃後も、第三者の保持者IDが維持されることを確認済み。
- 味方第三者保持中でも、手動UIの攻撃コマンドが有効になることを確認済み。
- 味方第三者保持中でも、AIが非保持者への基本攻撃と装備攻撃スキルを合法候補として生成することを確認済み。
- 保持者本人の攻撃後保持継続と、保持中の移動後攻撃候補を確認済み。
- スモーク、通常ヘッドレス、敵グループ指定ヘッドレスを完走済み。

## 32. 試合中オート・速度管理の簡素化

この節は2026-07-12時点の、試合中の味方オート操作と表示速度管理に関する正規仕様である。第29節までの操作方式モーダル、オート連動速度、独立スキップの記述と矛盾する場合は、この節と実装コードを優先する。

### 試合開始と状態管理

- 試合開始時の手動／AI操作方式選択モーダルは表示せず、試合画面を直接開始する。
- 新しい試合と再試合は、味方オートOFF、表示速度1倍で開始する。
- 試合単位の一時状態として、味方オート状態と表示速度を別々に保持する。自由試合設定JSONやマスターCSVへは保存しない。
- 味方オート状態と表示速度は、得点、リスタート、行動者変更、ターン更新では変更しない。
- 味方オート状態は敵AIへ適用しない。敵は従来どおりAIで行動する。

### 試合中の操作と表示

- 試合画面上部に `オート：OFF` / `オート：ON` ボタンと、`速度：1倍`～`速度：20倍` ボタンを表示する。
- オートボタンは味方オート状態だけを反転し、表示速度を変更しない。
- 速度ボタンはオート状態を変更せず、`1倍 → 2倍 → 5倍 → 10倍 → 20倍 → 1倍` の順で循環する。
- 20倍は通常の表示速度であり、専用スキップ状態ではない。
- 独立した「スキップ」「得点までスキップ」と「残りをAIに任せる」ボタンは試合画面へ表示しない。
- 全画面行動選択、行動予測、オプション、全ログ、リタイア確認などの既存モーダル表示中は、背面の試合操作とAI更新を停止する。

### オート切り替え

- 手動操作途中でオートをONにした場合は、未確定の対象選択、行動選択、スキル選択、仮移動を既存の取消処理で解除する。
- 仮移動は確定せず元の位置へ戻し、HP、MP、ボール、行動済み状態、クールタイム、使用回数を変更しない。
- 取消処理が例外で完了しなかった場合はオート切り替えを中止し、試合を継続する。
- オートON後は同じ現在行動者が未行動なら、既存の味方AI行動処理へ接続する。
- AI行動または演出中にオートをOFFにしても、現在の行動と演出は中断しない。完了後の次の味方行動者から手動操作へ戻る。
- 味方オートと敵AIは既存の共通候補生成、評価、行動決定、行動実行処理を使用する。

### 表示速度の適用

- 表示速度は、AI行動開始待機、行動開始表示、移動演出、攻撃・スキル結果、判定表示、メッセージ、得点・リスタートに接続される既存UI演出時間へ適用する。
- 速度変更後に開始する演出区間から新しい倍率を使用する。開始済み区間を途中で再計算する必要はない。
- 手動操作時の判定確認と決定入力は、速度倍率にかかわらずプレイヤー入力を待つ。
- 速度倍率はダメージ、成功率、乱数、AI評価、行動順、得点、負傷などのルール計算へ適用しない。
- 速度インデックスが範囲外、または許可されていない倍率になった場合は1倍へ補正し、試合を継続する。

### 旧スキップ互換

- 旧スキップ用の内部フィールドと互換メソッドは現時点で残っているが、新しい画面、入力、通常演出経路からは使用しない。
- 新しい試合では旧スキップ状態を常に無効として初期化する。
- 旧スキップ専用の短縮演出時間、得点時継続確認、速度復元処理は通常の試合進行へ適用しない。

### 確認済み範囲

- 新しい試合が操作方式モーダルなし、オートOFF、速度1倍で開始することを確認済み。
- 試合画面に独立スキップ、ラウンド操作方式、「残りをAIに任せる」ボタンが表示されないことを確認済み。
- 速度が2倍、5倍、10倍、20倍、1倍の順に循環し、オート状態を維持することを確認済み。
- 速度5倍のままオートON／OFFを切り替えても、5倍が維持されることを確認済み。
- 仮移動中のオートONで仮移動が取り消され、行動者の位置と未行動状態が維持されることを確認済み。
- Python構文確認と `python main.py --smoke-test` を完走済み。

## 33. 戦闘中能力確認UI

### 5能力の表示

- パワー、マジック、スピード、テクニック、スタミナを固定順で表示する。
- 現在値は、ダメージ、移動、パス、AI判断などが使用する既存の `MatchGame.effective_stat()` から取得する。UI専用の負傷、一時効果、保持スキル、上下限計算は実装しない。

- 正負の個別効果が相殺され、最終値が基礎値と同じ場合は能力欄を補正なし表示にするが、個別効果は状態変化一覧へ残す。
- 実効能力を取得できない場合は該当する基礎値を通常色で表示し、警告ログへ記録する。

### 状態変化一覧

- 能力欄の下へ、取得できた負傷、能力上昇・低下の一時効果、ボール保持スキル、防御状態、移動力低下、反応スキルを効果ごとに分けて表示する。
- 能力変更スキルは効果名、対象能力、変化量、残り行動数を表示する。残り回数を取得できない効果は解除条件または「解除条件不明」を表示する。
- ボール保持スキルは既存の `ball_hold_skills()` と `ball_hold_status()` を使用し、効果名、能力変化、解除条件「ボール保持中」を表示する。
- 負傷は負傷率と5能力への負傷補正であること、防御・移動力低下・反応スキルは取得できる解除条件を表示する。
- 適用中の表示対象効果がない場合は「能力変化なし」と表示する。
- 一覧は4項目を同時表示し、マウスホイールおよび画面内の上下ボタンでスクロールする。上下ボタンはタッチ入力でも既存の共通ポインター処理から操作できる。
- 一部の一時効果データが不正でも、その項目だけを警告ログ付きで無視し、取得できたHP、MP、能力、状態効果の表示を継続する。

### 入力停止と無副作用

- モーダル表示中は `update()` の試合進行を停止し、AI行動、得点開始判定、行動者変更処理を進めない。
- ポインター入力は閉じる・一覧上下ボタンだけへ限定し、モーダル外のクリックやタップをフィールド、コマンド、上部操作へ伝播させない。
- マウスホイールは状態変化一覧だけへ渡し、背面のメニューや一覧をスクロールしない。
- モーダルの生成、描画、スクロール、開閉ではルール層の更新処理と乱数処理を呼び出さない。

### 確認済み範囲

## 34. クエスト戦闘ルール切り替えとリタイア直接操作

この節は2026-07-28時点の、クエストデータによる戦闘ルール切り替え、マナ奪還、儀式維持、および戦闘画面のリタイア操作に関する正規仕様である。従来の得点制に関する記述と矛盾する場合、クエスト起点の戦闘についてはこの節と実装コード、`data/csv/quests.csv` を優先する。

### クエストデータ

- 現在のプロジェクトではクエスト1件が1戦闘ウェーブに相当し、`quests.csv` の各行へルールを設定する。
- `rule_type` は `1` が浄化運搬、`2` がマナ奪還、`3` が儀式維持。
- `required_hold_turns` は儀式維持で必要な連続保持ターン数。3ターンと5ターンの訓練データを実装済み。
- `initial_ball_holder` はキャラクターID、または出場順を表す `ally:1`、`enemy:1` 形式で指定する。
- ルール列が存在しない、または `rule_type` が空欄の旧クエストデータは浄化運搬として読み込む。
- 未対応の `rule_type` はクエストID、ウェーブ相当値、設定値をエラーログへ出力して開始を中止する。他ルールとして推測しない。
- 儀式維持の必要ターン数が空欄、数値変換不能、または0以下の場合は警告ログを出して3ターンへ補正する。
- マナ奪還または儀式維持で指定陣営の初期保持者を取得できない場合は、ボールなしで開始せず、クエストID、ウェーブ相当値、ルール、保持者指定を含むエラーで開始を中止する。

### 浄化運搬

- ウェーブ開始時は指定された味方がボールを保持する。
- 味方のボール保持者が相手側の浄化地点へ到達した場合だけ既存の得点処理を行い、クエストの先取得点へ到達すると勝利する。
- 敵に奪われた場合、落球した場合、味方が奪い返した場合も戦闘を継続し、既存の移動、攻撃、パス、スティール、パスカット、ルーズボール回収を使用する。
- 既存クエストはルール1と `ally:1` を設定し、従来のゴール到達処理へ接続する。

### マナ奪還

- ウェーブ開始時は `initial_ball_holder` で指定された敵がボールを保持する。
- ボール所有権を更新する共通 `set_ball_holder()` 処理で、保持側が味方になった時点に「マナボールを奪還しました」と記録し、0対0の状態でも味方勝利として試合を終了する。
- 判定はスティール専用ではなく、パスカット、攻撃後の落球回収、通常のルーズボール回収、その他の共通所有権更新経路へ適用する。
- 敵から別の敵への移動、または敵が落球してルーズボールになった時点ではクリアしない。
- 味方取得と同じ所有権更新内で終了を確定し、次の行動者へは進めない。
- マナ奪還中は保持者がゴールへ入っても既存得点処理を実行しない。

### 儀式維持

- ウェーブ開始時は `initial_ball_holder` で指定された味方がボールを保持し、連続保持ターン数を0から開始する。
- 行動者単位ではなく、味方と敵を含む行動順が一巡した既存ラウンド終了箇所で1回だけ判定する。
- 一巡終了時に味方が保持していれば1増加し、必要ターン数以上になった時点で「儀式が完了しました」と記録して味方勝利にする。
- 味方同士のパスや味方による回収で保持者が変わっても、味方側の保持が続く限りカウントを維持する。
- 敵が取得した時点、またはルーズボールになった時点でカウントを0へ戻す。1以上から中断した場合は「儀式維持が中断されました」と記録する。
- 味方が再取得した場合は「儀式維持を再開します」と記録し、次の有効な一巡終了時から1として数え直す。
- 儀式維持中は保持者がゴールへ入っても既存得点処理を実行しない。

### 戦闘画面表示

- 戦闘画面上部へ現在のルール名と勝利条件を表示する。
- 浄化運搬は「勝利条件：マナボールを浄化地点へ運ぶ」、マナ奪還は「勝利条件：敵からマナボールを奪還する」と表示する。
- 儀式維持は「勝利条件：マナボールをNターン維持する」と、現在値「儀式維持：現在値／必要値ターン」を表示する。
- 既存のボール保持者欄をそのまま使用し、味方、敵、ルーズボールを識別する。
- 専用画像、アニメーション、大型ポップアップは追加しない。

### リタイア操作

- 戦闘画面右下に「リタイア」と「全ログ」を常時表示する。行動演出中または試合終了後はリタイアを無効化する。
- 「リタイア」を押すと既存の確認モーダルを表示し、確定、取消、Escape以外の背面入力とAI進行を停止する。
- 通常クエストで確定した場合は敵勝利、終了理由 `retire` としてリザルトへ接続する。
- 自由試合で確定した場合は勝敗なし、終了理由 `debug_interrupt` として終了する。
- オプション内の「リタイア」も同じ確認処理へ接続し、直接ボタンと結果を共通化する。

### 実装データと確認済み範囲

- `training_recapture`、`training_ritual_3`、`training_ritual_5` をルール確認用クエストとして追加済み。
- 旧CSV互換、初期保持者、敵落球時の継続、敵同士の所有移動、味方取得時の奪還終了、味方内保持変更、敵保持・ルーズ時の儀式リセット、3ターン・5ターン完了を自動テストで確認済み。
- マナ奪還のヘッドレス試合で敵保持開始、味方スティール直後の0対0勝利、次の敵行動へ進まないことを確認済み。
- 直接リタイアボタンが画面内にあり、確認後に通常試合を `retire` で終了すること、オプション内の既存経路も維持されることをUIテストで確認済み。
- Python構文確認、対象テスト、`python main.py --smoke-test`、差分チェックを完走済み。
