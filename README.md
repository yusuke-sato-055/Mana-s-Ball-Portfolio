# BaseFolder

このフォルダは、ゲーム制作で共通利用するベースフォルダです。
ゲーム本体の実装やデータから参照する素材置き場をまとめ、プロジェクトごとの雛形として使うことを想定しています。

## Mana's Ball の起動

Python 3.11とPygame 2系を使用する、3対3のターン制球技プロトタイプです。

```powershell
python main.py
```

ホーム画面の「クエスト」からクエスト選択画面へ進み、挑戦するクエストを選んでからパーティー編成を行います。クエスト用編成では一覧から重複しない味方を選び、敵グループ、フィールド、出場人数、勝利条件、戦闘ルールは選択したクエスト設定から決まります。職種・属性フィルターとCSV順・名前・主要能力順の並び替え、キャラクター詳細、チーム合計比較を利用できます。キャラクター詳細の「スキル交代」では、現在のスキル枠を有効な実装済みスキルへ一時的に置換できます。味方編成枠の「出」は初期出場、「控」はベンチを表します。

ホーム画面の「自由試合」では同じ編成画面を使用し、敵グループ方式と敵手動編成方式を切り替えられます。味方と敵の参加人数、出場人数、ベンチ人数、キャラクター能力、スキル、敵手動編成時のAIプロフィール、初期配置、先取点、ターン制限、交代、負傷を設定できます。確定した設定は `data/save/debug_match_last.json` へ自由試合設定として1件だけ保存でき、試合開始時にも自動保存されます。旧デバッグ設定JSONも読み込み、次回画面表示時の自動復元、最後の設定の再読込、CSV初期設定への復帰が可能で、マスターCSVや正式セーブデータは変更しません。

味方の手動行動開始時は現在行動者が自動選択され、その付近へ「攻撃・移動・ボール・スキル・待機」が自動表示されます。フィールドは13×5マス、左右のゴールはそれぞれ3×3マスです。ボール保持者が相手ゴール内の移動先へ到着すると移動を確定し、主行動を選ばず得点します。ボールを持っていないキャラクターも行動順どおり行動できます。攻撃は固定の主系統に応じて「攻撃・物理」または「攻撃・魔法」を使用し、ボール保持者も攻撃できます。通常パスとパススキルは主系統を自動使用し、「物理パス」または「魔法パス」と表示します。通常パス、ボールキープ、パスカット、スティールなどは「ボール」コマンドへまとめています。ボール保持スキルは所有者本人の保持中だけ自動発動し、コマンド候補には表示しません。移動後は攻撃、ボール行動、支援スキルまたは待機を選択できますが、影渡りや突破など使用者自身が移動する行動は選択できません。ゴールしない移動は主行動の確定前まで取り消せます。手動モードでは判定結果をクリックまたはタップするまで保持し、オート時は設定時間で進行します。タップ入力も同じルールと座標変換を使用します。

浄化運搬では、行動順が一巡しても位置、ボール、HP、MPは維持され、ボール保持者が浄化地点へ到達すると既存の得点・再開処理へ進みます。設定された先取得点へ到達すると勝利します。マナ奪還では敵保持から開始し、味方がボールを取得した時点で勝利します。儀式維持では味方保持から開始し、行動順が一巡するたびに保持ターンを数え、敵保持またはルーズボールになると0へ戻します。現在のルール名、勝利条件、儀式維持数は戦闘画面上部に表示されます。

能力は「物理・魔法」の系統と、「パワー・スピード・テクニック・スタミナ」の基礎能力に分類します。試合中に増減するリソースはHPとMPだけです。スタミナは消費・回復しない固定能力として、防御や回復計算から参照します。保持・奪取・争奪のチーム状態はボール保持者から自動判定されます。

自動テスト、画面初期化、無人試合は以下で確認できます。

```powershell
python -m unittest discover -s tests -v
python main.py --smoke-test
python main.py --headless-sim
python main.py --headless-sim --enemy-group training_group --seed 7
python main.py --headless-sim --quest training_1v3 --seed 7
```

クエスト起点の戦闘は `data/csv/quests.csv` からフィールド、試合設定、敵グループを結合します。外観は
`field_settings.csv`、マス構造と配置候補は `data/field_layouts.json`、再利用可能な試合ルールは
`match_rules.csv` で管理します。従来の `match_settings.csv` は共通計算値とデバッグ直接開始の互換用です。
`quests.csv` の `rule_type` は `1` が浄化運搬、`2` がマナ奪還、`3` が儀式維持です。
`required_hold_turns` は儀式維持の必要ターン数、`initial_ball_holder` は `ally:1`、`enemy:1` またはキャラクターIDで初期保持者を指定します。
ルール列のない旧クエストデータは浄化運搬として読み込みます。現在の実装ではクエスト1件が1戦闘ウェーブに相当します。
音声は `assets/bgm/<ID>.ogg` と `assets/se/<ID>.ogg` を参照し、素材がない場合は警告後に無音で続行します。
クエスト選択画面で1対1、1対3、3対3、4対4、6対6などの有効なクエストを選択します。
編成枠の「出」は初期出場、「控」はベンチを表し、標準3対3でも4人目以降をベンチへ追加できます。
戦闘画面右下の「リタイア」は確認画面を経て試合を終了します。通常クエストでは味方敗北、自由試合では勝敗なしのデバッグ中断として扱います。

## 同一Wi-Fi内のブラウザで起動

pygbag版もPC版と同じゲーム処理と入力処理を使用します。スマホでは横向きにし、タップをマウスクリックとして操作します。

まず `ipconfig` で、現在接続しているWi-FiのIPv4アドレスを確認します。次に、PC版を起動するものと同じPython環境で、プロジェクト直下から以下を実行します。

```powershell
python -m pygbag --bind <PCのIPv4アドレス> --port 8000 .
```

PCと同じWi-Fiへ接続したPCブラウザおよびスマホブラウザで、以下を開きます。

```text
http://<PCのIPv4アドレス>:8000/
```

スマホからは `localhost`、`127.0.0.1`、`0.0.0.0` ではなく、確認したPCのIPv4アドレスを使用してください。接続できない場合は、PC側でポート8000が待ち受けていることと、Windowsファイアウォールのプライベートネットワーク許可を確認してください。

試合設定は `data/csv/match_settings.csv`、スキル全体定義は `data/csv/skills.csv`、1スキル最大5件の共通効果は `data/csv/skill_effects.csv` で変更できます。能力差ダメージ倍率、カット／パスカット基礎成功率、成功率上下限、基本パス射程、距離補正も試合設定から調整できます。

## フォルダ構成

- `assets/`: 画像、音声、フォントなどの素材を配置するフォルダです。
- `assets/images/`: 背景、キャラクター、敵、UI素材などの画像を配置します。
- `assets/images/characters/portraits/`: キャラクターの立ち絵画像を配置します。
- `assets/images/characters/icons/`: キャラクターのアイコン画像を配置します。
- `assets/bgm/`: BGM素材を配置します。
- `assets/se/`: 効果音素材を配置します。
- `assets/fonts/`: フォント素材を配置します。
- `data/`: ゲームで利用するマスターデータを配置するフォルダです。
- `data/csv/`: CSV形式のマスターデータを配置します。
- `data/csv/characters.csv`: 最低限のキャラクターデータを定義するCSVです。
- `data/csv/enemies.csv`: 敵単体の能力、スキル3枠、基本AIを定義するCSVです。
- `data/csv/enemy_groups.csv`: 敵3体、能力倍率、共通・スロット別AIを定義するCSVです。
- `.keep`: 空フォルダをGit上でも残すための管理用ファイルです。

## キャラクターデータ

`data/csv/characters.csv` には、ゲームで参照する最低限のキャラクター情報を定義しています。
現在の主な列は以下の通りです。

- `char_id`: キャラクターを一意に識別するIDです。キャラクター画像もこの `char_id` をキーにして管理します。
- `name`: キャラクター名です。
- `element_id`: キャラクターの属性IDです。
- `class_id`: キャラクターのクラスIDです。
- `max_hp`, `max_mana`: 試合中のHP、MPの最大値です。
- `stamina`: パワー、スピード、テクニックと同じ固定の基礎能力です。旧CSVの `max_stamina` も互換入力として読み込めます。
- `physical`, `magic`: 物理・魔法の系統値です。
- `power`, `speed`, `technique`, `stamina`: 威力、行動速度、精密操作、防御などに使う基礎能力です。
- `physical_skill_level`, `magic_skill_level`: 物理・魔法スキルの使用可能レベルです。
- `move_range`, `pass_range`: 移動力と通常パス距離です。
- `skills`: `|` 区切りの習得スキルIDです。
- `primary_system`: 試合中に変化しない主系統で、`physical` または `magic` を指定します。

`attack`、`defense`、`accuracy`、`pass_range` などの旧専用能力列は旧データ読込の互換用に残しています。新しい共通スキルは系統と基礎能力を効果CSVから参照します。

`element_id` は、現時点では以下の対応を想定しています。

| element_id | 属性 |
| --- | --- |
| 1 | 火 |
| 2 | 水 |
| 3 | 風 |

`class_id` は、現時点では以下の対応を想定しています。

| class_id | クラス |
| --- | --- |
| 1 | 戦士 |
| 2 | 魔法使い |
| 3 | 盗賊 |
| 4 | 僧侶 |
| 5 | 格闘家 |

たとえば `char_id` が `10` の `ブリギッド` は、`element_id` が `1`、`class_id` が `1` のため、火属性の戦士として扱います。
画像素材を用意する場合は、キャラクター名ではなく `char_id` を基準に参照できるようにしておくと、名前変更や多言語対応の影響を受けにくくなります。

## キャラクター画像の利用

キャラクターの立ち絵やアイコンは、`data/csv/characters.csv` の `char_id` と同じ値をファイル名にして配置します。
キャラクター名ではなく `char_id` を使って画像を指定することで、表示名を変更しても画像参照を修正せずに済みます。

標準の配置ルールは以下の通りです。

| 用途 | 配置先 | ファイル名 |
| --- | --- | --- |
| 立ち絵 | `assets/images/characters/portraits/` | `<char_id>.png` |
| アイコン | `assets/images/characters/icons/` | `<char_id>.png` |

例:

| char_id | キャラクター名 | 立ち絵 | アイコン |
| --- | --- | --- | --- |
| 10 | ブリギッド | `assets/images/characters/portraits/10.png` | `assets/images/characters/icons/10.png` |
| 21 | マリナ | `assets/images/characters/portraits/21.png` | `assets/images/characters/icons/21.png` |

実装では、キャラクターデータを読み込んだあとに `char_id` から画像パスを組み立ててください。

```text
立ち絵: assets/images/characters/portraits/{char_id}.png
アイコン: assets/images/characters/icons/{char_id}.png
```

画像ファイルが存在しない場合に備えて、ゲーム側では仮画像や共通アイコンへフォールバックできるようにしておくと安全です。
たとえば `char_id` が `10` のキャラクターを表示する場合、立ち絵は `portraits/10.png`、アイコンは `icons/10.png` を参照します。

## Git管理について

このベースフォルダをGitで管理する場合でも、すべてのファイルをGitに上げるわけではありません。

Gitに上げない例外の例:

- Pythonのキャッシュやビルド生成物
- 仮想環境フォルダ
- テストや解析ツールのキャッシュ
- 実行ログ
- サイズが大きい素材の元データ
- 配布権限やライセンス確認が必要な素材
- 作業中、仮置き、差し替え予定のアセット

現在の `.gitignore` では、主にPython系のキャッシュ、仮想環境、ログファイルを除外しています。
アセット類はプロジェクトの利用条件に応じて、Gitに含めるものと含めないものを分けて管理してください。

## アセット運用

`assets/` 配下にはゲームで参照する素材を置きます。
ただし、画像、BGM、効果音、フォントなどは容量が大きくなりやすく、またライセンスや配布条件の確認が必要です。

そのため、以下のような運用を推奨します。

- 実行や表示確認に必要な最低限の素材はGit管理する。
- 高解像度の元データ、編集用ファイル、未確定素材はGitに含めない。
- 外部配布できない素材はローカル管理または別ストレージで管理する。
- Gitに含めない素材が必要な場合は、配置場所と入手方法を別途メモしておく。
- 空フォルダを残したい場合は `.keep` を配置する。

## 文字の設定
実装時は、日本語表示が文字化けしないように、必ず以下のフォントファイルを使用してください。

assets/fonts/NotoSansJP-VariableFont_wght.ttf

開発環境上の配置場所は以下です。

C:\Users\ysato\OneDrive\Desktop\プログラム\ゲーム作成\260617Dicesuccess\assets\fonts\NotoSansJP-VariableFont_wght.ttf

画面上に日本語テキストを表示する処理では、OS標準フォントやデフォルトフォントに依存せず、上記の NotoSansJP-VariableFont_wght.ttf を明示的に読み込んで使用してください。

## 注意

別環境でこのフォルダを使う場合、Gitに含まれていないアセットが不足している可能性があります。
画像や音声が表示・再生されない場合は、まず `assets/` 配下に必要な素材が配置されているか確認してください。
